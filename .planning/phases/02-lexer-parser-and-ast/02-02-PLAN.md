<objective>
Implement the full WDL 1.2 lexer using the Rob Pike state-function pattern. The lexer handles
three modes: normal WDL tokenization, command-brace mode (both ~{} and ${} are placeholders),
and command-heredoc mode (only ~{} is a placeholder; ${...} passes through as raw text).

Purpose: The parser (Plans 03, 04, 05) is built on top of this lexer. Getting command block
tokenization correct here prevents silent parse-tree corruption downstream.

Output: wdl/lexer/lexer.go (full implementation), wdl/lexer/lexer_test.go (real tests replacing stubs)

  <behavior>
    - NewLexer(file string, src []byte) *Lexer creates a lexer; Next() returns the next Token
    - Token struct has fields: Type TokenType, Val string, Pos ast.Pos
    - TokenType is defined as type TokenType int with iota constants covering all WDL keywords, operators, punctuation, and special tokens
    - tokEOF is emitted at end of input; tokError is emitted on unrecognized input with Val = error message
    - Keywords have dedicated token types: tokVersion, tokTask, tokWorkflow, tokStruct, tokImport, tokAs, tokAlias, tokInput, tokOutput, tokCommand, tokRuntime, tokRequirements, tokHints, tokMeta, tokParamMeta, tokCall, tokScatter, tokIn, tokIf, tokThen, tokElse, tokAfter, tokEnv, tokBoolean, tokInt (type), tokFloat (type), tokString (type), tokFile (type), tokDirectory (type), tokArray, tokMap, tokPair, tokObject, tokNull, tokTrue, tokFalse
    - Operators: tokAssign (=), tokPlus (+), tokMinus (-), tokStar (*), tokSlash (/), tokPercent (%), tokStarStar (**), tokEqEq (==), tokNotEq (!=), tokLt (<), tokLtEq (<=), tokGt (>), tokGtEq (>=), tokAnd (&&), tokOr (||), tokNot (!), tokDot (.), tokQuestion (?), tokPlus already covers +
    - Punctuation: tokLBrace ({), tokRBrace (}), tokLParen ((), tokRParen ()), tokLBracket ([), tokRBracket (]), tokComma (,), tokColon (:), tokArrow (->), tokHeredocOpen (<<<), tokHeredocClose (>>>), tokTripleTilde (~~~) not needed
    - String delimiters: tokStringOpen ("), tokStringClose (")
    - Command-mode tokens: tokCommandContent (raw text inside command block), tokPlaceholderOpen (~{ or ${ in brace mode, ~{ in heredoc mode), tokPlaceholderClose (})
    - tokIdent for identifiers and unrecognized names; tokIntLit, tokFloatLit for numeric literals
    - In command-brace mode (lexCommandBrace): scan character by character matching COMMAND1_CHAR pattern — any char that is not ~, $, or }. When ~{ or ${ is seen, emit tokPlaceholderOpen and push mode. On { seen during placeholder, increment braceDepth. On }, if braceDepth > 0 decrement; else emit tokPlaceholderClose and pop mode. On } with no open placeholder, emit tokRBrace and exit command-brace mode.
    - In command-heredoc mode (lexCommandHeredoc): scan matching COMMAND2_CHAR — any char that is not ~ or >. When ~{ is seen, emit tokPlaceholderOpen and push mode. On ~  NOT followed by {, emit as raw content. On >>> sequence, emit tokHeredocClose and exit heredoc mode. ${...} scanned as raw content ($ is not special).
    - Placeholder re-entry: when inside a placeholder (normal mode re-entered), the lexer resumes normal tokenization. When the matching } is found and braceDepth returns to 0, emit tokPlaceholderClose and pop mode.
    - Mode stack: maintain a stack ([]lexMode) for re-entrant placeholder sub-lexing. Modes: modeNormal, modeCommandBrace, modeCommandHeredoc, modePlaceholder.
    - String mode: on " in normal mode, enter string scanning. Inside strings, ~{ and ${ are placeholder delimiters (same brace-depth tracking). On closing ", exit string mode. tokStringOpen and tokStringClose bracket the string parts; tokCommandContent represents raw string fragments.
    - Track line/col: increment line counter on \n; col resets to 1. Every emitted token gets the Pos of its first byte.
    - After the keyword "command" is recognized, peek at the next non-whitespace: if {, the next token is tokLBrace and lexer transitions to command-brace mode. If <<<, emit tokHeredocOpen and transition to heredoc mode.
  </behavior>

Import "github.com/bioflowy/flowy/wdl/ast" for ast.Pos.

Key implementation notes:
1. Use a synchronous pull model (Next() advances state, no goroutines or channels).
2. Implement peek(n int) byte to look ahead without consuming. Use advance() to consume one byte.
3. For keyword disambiguation, lex identifiers first and then check a keywords map[string]TokenType.
4. The command mode transition happens AFTER the parser consumes the "command" keyword token — the lexer needs a SetCommandMode(style CommandStyle) method that the parser calls, OR the lexer detects command-block start automatically. Use automatic detection: after emitting tokCommand, immediately peek/consume whitespace, then check for { vs <<<. Emit the open token and set mode.
5. Brace depth for placeholder close detection: maintain braceDepth int. Inside a placeholder (after tokPlaceholderOpen), each { increments braceDepth; each } decrements. Only emit tokPlaceholderClose when braceDepth == 0 AND we are inside a placeholder.
6. Do NOT use regexp in the hot path — use direct byte/rune comparisons.
7. ** is two consecutive * characters — check for ** before emitting a single *.
8. For +? type quantifier: the lexer emits tokPlus and tokQuestion as separate tokens; the parser handles the +? combination when parsing types.
