Source: Phase 25 UI-SPEC typography contract. No changes. Information-dense GitHub-style UI (REQUIREMENTS.md design direction) calls for 14px body.

## Screen Inventory

Phase 26 introduces two new screens and modifies one existing component.

### Screen 1: Login Page (`/login`)

Full-page centered layout. No sidebar. No AppShell.

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│                                                         │
│            ┌───────────────────────────┐                │
│            │  flowy            (20px)  │                │
│            │  Sign in to continue      │                │
│            │  ───────────────────────  │                │
│            │  Username           [   ] │                │
│            │  Password           [   ] │                │
│            │                           │                │
│            │  [Error message if any  ] │                │
│            │                           │                │
│            │  [      Sign in      ]    │                │
│            └───────────────────────────┘                │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

- Layout: `min-h-screen flex items-center justify-center bg-background`
- Card: shadcn/ui `<Card>` — width `w-full max-w-sm`, padding `p-6`
- Card header: app name ("flowy") at Display (28px / semibold), subtitle ("Sign in to continue") at Body (14px / regular / muted-foreground). Primary visual anchor: the "flowy" display heading (28px/semibold) draws the eye first; the full-width "Sign in" button is the action focal point.
- Form: shadcn/ui `<Form>` with react-hook-form + zod
- Username field: shadcn/ui `<Label>` + `<Input>` (type="text", autocomplete="username")
- Password field: shadcn/ui `<Label>` + `<Input>` (type="password", autocomplete="current-password")
- Error alert: shown below password field, above submit button. Destructive color. Text 12px/regular.
- Submit button: shadcn/ui `<Button>` full-width (`w-full`), variant="default" (accent/primary color)
- No "Forgot password" link (out of scope for v2.0)
- No "Register" link (admin-created accounts only)

### Screen 2: Account Page (`/account`)

Page within AppShell. Contains the Change Password section and logout action.

```
┌─────────────────────────────────────────────────────────┐
│  Sidebar (unchanged)  │  Account                        │

│                       │  Password                       │
│                       │  ─────────────────────────────  │

│                       │  [Sign out]  (button)           │

```

- Page heading: "Account" — Heading (20px / semibold)
- Section headings: "Password", "Session" — Label (12px / regular / muted-foreground), uppercase, letter-spaced
- "Change Password" button: variant="outline", opens `<ChangePasswordDialog>`
- "Sign out" button: variant="outline", triggers logout (clearAuth + navigate to /login)

### Modal: Change Password Dialog

Triggered from Account page. Uses shadcn/ui `<Dialog>`.

- Dialog title: "Change Password" — Heading (20px / semibold)
- Current password field: `<Label>` + `<Input>` (type="password", autocomplete="current-password")
- New password field: `<Label>` + `<Input>` (type="password", autocomplete="new-password")
- Confirm new password field: `<Label>` + `<Input>` (type="password", autocomplete="new-password")
- Inline validation: show error under each field when it fails (shadcn/ui `<FormMessage>`)
- Submit button: "Update password" — variant="default" (accent/primary), full-width
- Cancel button: "Keep current password" — variant="ghost", closes dialog without action
- On success: show success toast (sonner), reset form, close dialog

### Sidebar Modification: Account Area

Sidebar footer area updated from placeholder to functional:

- Show logged-in username: Body (14px / regular), with `<UserCircle>` icon (16px)
- "Sign out" as a clickable element (small button or link style) — destructive color on hover is NOT used here; use muted-foreground at rest, foreground on hover
- The account section opens the Account page on click of the username area

## Interaction States

Each interactive element must implement all listed states:

### Login Form Inputs (Username, Password)

| State | Visual |
|-------|--------|
| Default | `--input` border color, `--background` fill |
| Focus | `--ring` outline (2px), `--ring` border color |
| Error | `--destructive` border color, error message shown below |
| Disabled | 50% opacity (during form submission in-flight) |

### "Sign in" Button

| State | Visual |
|-------|--------|
| Default | `--primary` background, `--primary-foreground` text |
| Hover | Slightly lighter `--primary` (shadcn/ui default hover) |
| Active | Pressed scale (shadcn/ui default) |
| Loading | Disabled + spinner icon (lucide `<Loader2>` with `animate-spin`), text "Signing in..." |
| Disabled | 50% opacity |

Loading state is shown from form submit until API response. Prevents double-submit.

### Login Error Alert

| State | Visual |
|-------|--------|
| No error | Hidden (not rendered) |
| Credentials error | Visible alert in destructive color below password field |
| Account disabled | Visible alert in destructive color, distinct message |

Do not use toast for login errors — inline alerts are required so the user understands which form has the error.

### Change Password Dialog Submit

| State | Visual |
|-------|--------|
| Default | `--primary` background |
| Loading | Disabled + `<Loader2 animate-spin>`, text "Updating..." |
| Success | Dialog closes, sonner toast: "Password updated successfully" |
| Error | Inline error shown (wrong current password: "Current password is incorrect") |

### Sign Out Action

| State | Visual |
|-------|--------|
| Default | muted-foreground text, no background |
| Hover | foreground text |

No confirmation dialog for sign out. Action is reversible (user can log back in).

## Accessibility Requirements

All form elements must meet WCAG 2.1 AA:

- Every `<Input>` has an associated `<Label>` connected via `htmlFor` / `id` — shadcn/ui `<Form>` handles this automatically
- Error messages are associated with their input via `aria-describedby` — shadcn/ui `<FormMessage>` handles this
- Password inputs use `type="password"` — browsers handle masking natively
- Submit buttons never have empty `aria-label` — button text is always visible
- Focus must be trapped inside `<Dialog>` when open — Radix UI Dialog handles this
- Focus returns to trigger button after dialog close — Radix UI Dialog handles this
- Color is never the only indicator of error state — error message text is always shown alongside color change
