Per user decision: "flowy run --task <name> also goes through the server via a new POST /tasks/run endpoint (not local Docker)".

1. **internal/api/types.go** — Add task run DTO types:
   ```go
   // TaskRunRequest is the request body for POST /tasks/run.
   // Runs a single named task from a WDL file (used by flowy run --task).
   type TaskRunRequest struct {
       // WDLPath is the absolute path to the WDL file on the shared filesystem.
       WDLPath string `json:"wdl_path"`

       // TaskName is the name of the task to execute from the WDL file.
       TaskName string `json:"task_name"`

       // InputsJSON contains the task-level input values keyed by input name.
       InputsJSON map[string]interface{} `json:"inputs"`

       // RunID is an optional client-provided UUID hint (same as SubmitRequest.RunID).
       RunID string `json:"run_id,omitempty"`

       // SearchPaths are optional import search directories.
       SearchPaths []string `json:"search_paths,omitempty"`
   }

   // TaskRunResponse is the response body for POST /tasks/run.
   type TaskRunResponse struct {
       // RunID is the UUID assigned to this task run.
       RunID string `json:"run_id"`
   }
   ```

2. **internal/server/handlers.go** — Add `handleTaskRun` method:
   ```go
   func (s *Server) handleTaskRun(w http.ResponseWriter, r *http.Request)
   ```
   Implementation follows the same pattern as `handleSubmit`:
   - Decode `api.TaskRunRequest` from body
   - Validate: `WDLPath` and `TaskName` are required
   - Parse the WDL file (with SearchPaths if provided, same as handleSubmit)
   - Find the named task in `doc.Tasks` — if not found, return 400 "task not found: <name>"
   - Use client-provided RunID if non-empty, else generate UUID
   - Call `store.CreateRunDirs(s.cfg.BaseDir, runID)`
   - Marshal inputs, create run record in store (same as handleSubmit)
   - Launch background goroutine: `go s.runWorkflow(runCtx, runID, doc, req.InputsJSON)`
     Note: `runWorkflow` works here because a WDL file with tasks but no workflow
     will fail at `len(doc.Workflows) == 0`. To handle single-task execution, the
     simplest approach is to wrap the task in a synthetic single-task workflow document.
     Create a minimal `ast.Workflow` with one `ast.Call` referencing the task:
     ```go
     syntheticWF := &ast.Workflow{
         Name: req.TaskName + "_wrapper",
         Body: []ast.WorkflowElement{
             {Call: &ast.Call{Name: req.TaskName, Alias: req.TaskName}},
         },
     }
     doc.Workflows = append(doc.Workflows, syntheticWF)
     ```
     Then `runWorkflow` will execute it normally via the dispatch mechanism.
     Map task inputs to workflow-level inputs by prefixing with the call alias
     (the dispatch mechanism uses `callName.inputName` format for inputs).
   - Store cancel function in `s.runs[runID]`, same as handleSubmit
   - Return 201 with `TaskRunResponse{RunID: runID}`

3. **internal/server/server.go** — Register the route:
   ```go
   r.Post("/tasks/run", s.handleTaskRun)
   ```
   Place it next to the existing `r.Post("/tasks/claim", s.handleClaim)` line.
