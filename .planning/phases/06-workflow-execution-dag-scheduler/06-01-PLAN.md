    - TestBuildDAG_Parallel: two independent calls A, B with no deps both appear at indegree 0
    - TestBuildDAG_AfterDependency: call B after A produces edge A -> B even with no data-flow link
    - TestBuildDAG_Cycle: circular dependency A->B->A returns cycle error
    - TestBuildDAG_CallAlias: call with alias uses alias as node ID, not callee name
    - TestBuildDAG_MixedDataFlowAndAfter: call C depends on A via data-flow and B via after; both edges present
  </behavior>
  <action>
    1. Create `wdl/workflow/workflow.go` with:
       - Package declaration and imports
       - `RunWorkflow(ctx context.Context, doc *ast.Document, wfName string, jsonInputs map[string]interface{}, runner task.ContainerRunner, execRoot string) (map[string]values.Value, error)` — stub that returns `nil, fmt.Errorf("not yet implemented")` for now
       - `buildTaskIndex(doc *ast.Document) map[string]*ast.Task` — maps task.Name to *ast.Task

    2. Create `wdl/workflow/dag.go` with:
       - `dagNode` struct: `id string`, `node ast.WorkflowNode`, `deps []string`, `successors []string`, `indegree int`
       - `buildDAG(body []ast.WorkflowNode) (map[string]*dagNode, error)` — walks workflow body:
         - For `*ast.Call`: create node with id = call.Alias if non-empty, else call.Callee[len(Callee)-1]
         - Walk each call.Inputs expression to find identifier references matching other call names (data-flow edges)
         - Add after edges from call.After[]
         - For `*ast.Scatter`: recurse into scatter.Body to find nested calls (they participate in the DAG)
         - For `*ast.Conditional`: recurse into cond.Body similarly
         - For `*ast.Decl`: skip (not a DAG node; handled synchronously by scheduler)
       - `topoSort(nodes map[string]*dagNode) ([]string, error)` — Kahn's algorithm: start with indegree-0 nodes, process queue, detect cycles when len(order) != len(nodes)
       - Helper `collectCallDeps(inputs map[string]ast.Expr, knownCalls map[string]bool) []string` — walks expression tree for IdentExpr and GetExpr to find references to known call names

       IMPORTANT: For data-flow edge detection, walk input expressions looking for:
       - `*ast.IdentExpr` whose name matches a known call ID (rare but possible)
       - `*ast.GetExpr` whose Object is an `*ast.IdentExpr` matching a known call ID (common: `call_name.output_name`)

    3. Create `wdl/workflow/dag_test.go` — build AST nodes programmatically (not from WDL source) to test buildDAG and topoSort in isolation. Use package `workflow` (internal test). Create minimal ast.Call/Scatter/Conditional with just the fields buildDAG reads.

    Note on DAG scope for v1: buildDAG creates nodes ONLY for top-level calls (and calls nested within scatter/conditional). Scatter and Conditional nodes themselves are NOT separate DAG nodes — they are execution wrappers handled by the scheduler. The DAG tracks data dependencies between calls.

    REVISED approach: Actually, for the scheduler in Plan 02 to work correctly, the DAG should track top-level workflow body elements (calls, scatters, conditionals) as execution units. Calls inside a scatter are part of that scatter's execution, not independent DAG nodes. So:
    - Top-level `*ast.Call` → DAG node (id = alias or callee name)
    - Top-level `*ast.Scatter` → DAG node (id = "scatter_N" or derived from contained call)
    - Top-level `*ast.Conditional` → DAG node (id = "if_N" or derived)
    - `*ast.Decl` → NOT a DAG node (synchronous eval)

    For dependency detection on scatter/conditional nodes: walk their body recursively to find all call references (both produced outputs and consumed inputs). A scatter node depends on calls whose outputs are used in the scatter's expressions or its body's call inputs.
  </action>
