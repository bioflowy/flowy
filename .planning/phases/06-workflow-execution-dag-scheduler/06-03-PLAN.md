  <files>wdl/workflow/output.go, wdl/workflow/output_test.go</files>
  <behavior>
    - TestWriteOutputsJSON_Simple: workflow "myWf" with output "result"=IntValue(42) → file contains {"myWf.result": 42}
    - TestWriteOutputsJSON_FileRelativePath: FileValue("/tmp/exec/work/out.txt") with execRoot="/tmp/exec" → value is "work/out.txt" (relative)
    - TestWriteOutputsJSON_DirectoryRelativePath: DirectoryValue absolute → relative
    - TestWriteOutputsJSON_Array: ArrayValue of StringValues → JSON array of strings
    - TestWriteOutputsJSON_Null: NullValue → null in JSON
    - TestWriteOutputsJSON_MultipleOutputs: two outputs → both present with workflow_name prefix
    - TestWriteErrorJSON: TaskError{TaskName:"foo", ExitCode:1} → {"error": "...", "task": "foo", "exit_code": 1}
    - TestWriteErrorJSON_NonTaskError: generic error → {"error": "msg", "task": "", "exit_code": -1}
  </behavior>
  <action>
    Create `wdl/workflow/output.go`:

    1. `writeOutputsJSON(wfName string, outputs map[string]values.Value, execRoot string, destPath string) error`:
       - Build `map[string]interface{}` with keys formatted as `wfName + "." + outputName`
       - Values converted via `valueToJSONOutput(v, execRoot)` which is like valueToJSON but relativizes File/Directory paths
       - Use `json.MarshalIndent(data, "", "  ")` for readability
       - Write to destPath via os.WriteFile with 0644 permissions

    2. `valueToJSONOutput(v values.Value, execRoot string) interface{}`:
       - Same as valueToJSON but for FileValue and DirectoryValue: use `filepath.Rel(execRoot, path)` to make paths relative
       - For ArrayValue, MapValue, PairValue, StructValue: recurse with valueToJSONOutput
       - For NullValue: return nil (JSON null)
       - For primitives (Int, Float, String, Boolean): return Go primitive directly

    3. `writeErrorJSON(err error, destPath string) error`:
       - If err is *task.TaskError (use errors.As): extract TaskName, ExitCode, Error() message
       - If err is generic error: task="", exit_code=-1, error=err.Error()
       - Marshal struct `{"error": msg, "task": name, "exit_code": code}`
       - Write to destPath

    Create `wdl/workflow/output_test.go`:
    - Test both functions with various value types
    - Use t.TempDir() for output file paths
    - Verify JSON content by unmarshaling and checking fields
  </action>
  <verify>

  </verify>

  <name>Task 2: Wire output writing into RunWorkflow and implement fail-fast cancellation</name>
  <files>wdl/workflow/workflow.go, wdl/workflow/scheduler.go, wdl/workflow/scheduler_test.go</files>
  <behavior>
    - TestRunWorkflow_OutputsJSON: successful workflow → outputs.json exists in execRoot with correct content
    - TestRunWorkflow_FailFast_ErrorJSON: task fails → error.json exists, outputs.json does NOT exist
    - TestRunWorkflow_FailFast_CancelsOthers: task A fails while task B is running → B receives context cancellation
    - TestRunWorkflow_WorkflowOutputs: workflow with output section → outputs collected from workflow env, not raw call outputs
    - TestRunWorkflow_EndToEnd: multi-call workflow with scatter and conditional → correct outputs.json written
  </behavior>
  <action>
    1. Update `wdl/workflow/workflow.go` RunWorkflow to:
       - After scheduler.run() completes successfully:
         - Evaluate workflow output declarations (wf.Outputs) against final env
         - Call writeOutputsJSON(wf.Name, outputs, execRoot, filepath.Join(execRoot, "outputs.json"))
         - Return outputs map
       - On error from scheduler.run():
         - Call writeErrorJSON(err, filepath.Join(execRoot, "error.json"))
         - Do NOT write outputs.json (locked decision)
         - Return nil, err

    2. Update `wdl/workflow/scheduler.go`:
       - Ensure the scheduler's error handling correctly propagates task failures:
         - When a completionMsg arrives with err != nil, the errgroup's context is already cancelled (errgroup does this automatically when g.Go's function returns non-nil)
         - The scheduler should stop dispatching new nodes and drain remaining running nodes
         - Return the first error encountered
       - Wrap task errors to preserve *TaskError type for writeErrorJSON to extract

    3. Evaluate workflow outputs:
       - `collectWorkflowOutputs(wf *ast.Workflow, env *eval.Env) (map[string]values.Value, error)`:
         - For each decl in wf.Outputs:
           - Evaluate decl.Expr against env (workflow env contains all call outputs)
           - Bind result to decl.Name
         - Return map[string]values.Value

    4. Update `wdl/workflow/scheduler_test.go`:
       - TestRunWorkflow_OutputsJSON: run workflow, verify outputs.json file content
       - TestRunWorkflow_FailFast_ErrorJSON: mock runner returns error for one task, verify error.json written, outputs.json absent
       - TestRunWorkflow_FailFast_CancelsOthers: two parallel tasks, first fails quickly, verify second receives context.Canceled (mock checks ctx.Err())
       - TestRunWorkflow_WorkflowOutputs: workflow with `output { Int result = my_call.value }` → outputs.json has `wfName.result` key
       - TestRunWorkflow_EndToEnd: build a realistic multi-call workflow with scatter + conditional + outputs

    All tests use t.TempDir() for execRoot, mock runners, and programmatic AST construction.
