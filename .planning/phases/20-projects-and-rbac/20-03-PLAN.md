   - `projectIDFromContext(ctx context.Context) string`: calls projectFromContext(ctx), returns proj.ID if not nil, empty string otherwise. This is the single point where project context connects to run creation — per research pitfall 5 (avoid handler duplication).

2. Modify handleSubmit in internal/server/handlers.go:
   - After creating the Run struct and before calling store.CreateRun, set: `run.ProjectID = projectIDFromContext(r.Context())`
   - This is a single-line addition. When no project is in context (auth-disabled path), ProjectID remains empty string, which maps to NULL in SQLite.
   - The same handleSubmit function is used by both /workflows and /projects/{slug}/runs/submit routes.

3. Similarly for handleTaskRun (POST /tasks/run equivalent under project scope if needed): add ProjectID from context. If task runs are not exposed under project scope yet, skip this — it's a daemon endpoint.

4. Update internal/server/server.go newRouter():
   - In the auth-enabled branch, inside the existing `/projects/{slug}` route group (from Plan 02), add a runs sub-resource:
     ```go
     // Runs sub-resource (project-scoped workflow runs)
     r.Route("/runs", func(r chi.Router) {
         r.With(s.projectRoleRequired("executor")).Post("/submit", s.handleSubmit)
         r.With(s.projectRoleRequired("executor")).Post("/task-run", s.handleTaskRun)
         r.With(s.projectRoleRequired("viewer")).Get("/{id}/status", s.handleStatus)
         r.With(s.projectRoleRequired("viewer")).Get("/{id}/outputs", s.handleOutputs)
         r.With(s.projectRoleRequired("executor")).Post("/{id}/abort", s.handleAbort)
     })
     ```
   - REMOVE the old /workflows routes from the auth-enabled JWT group (they are now under /projects/{slug}/runs/...). The auth-disabled branch keeps /workflows routes unchanged.
   - Keep daemon routes (/tasks/claim, /tasks/{id}/result, /heartbeat) in the daemon-authenticated group unchanged.
