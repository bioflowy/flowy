## Component Inventory

### RunWorkflowDialog

Dialog width: `sm:max-w-lg` — wider than existing `sm:max-w-md` to accommodate dynamic input form with multiple fields.

Structure:
1. `DialogHeader` — Title: "Run Workflow", Description: "Configure inputs and submit execution."
2. Version/tag selector — `Select` component, label "Version", options from available tags. Default: "latest" if present, else first entry.
3. Digest display — `text-xs text-muted-foreground` below the Select showing selected version's truncated digest.
4. `Separator` — between version selection and dynamic input form section.
5. Dynamic input form — one `FormField` per declared workflow input (see Input Field Types below).
6. `DialogFooter` — "Discard" (ghost variant) + "Run Workflow" (default variant with Loader2 when pending).

### Input Field Types

| WDL Type | Control | Notes |
|----------|---------|-------|
| String | `Input` (type="text") | Placeholder: "Enter a string value" |
| Int | `Input` (type="number", step="1") | Placeholder: "Enter an integer" |
| Float | `Input` (type="number", step="any") | Placeholder: "Enter a decimal number" |
| Boolean | `Checkbox` (shadcn checkbox component) | Label rendered inline beside checkbox; no separate Input |
| File | `Input` (type="text") | Placeholder: "e.g., s3://bucket/path or /absolute/path" + `Info` icon tooltip |
| Array / Map / Struct | `Textarea` | Placeholder: "Enter valid JSON" + helper text: "Use JSON format, e.g. [\"a\", \"b\"]" |

Tooltip for File inputs: Triggered by `Info` icon (lucide-react, `h-4 w-4`). Content: "Enter a server-accessible path. Browser file paths are not supported. Use s3://, /absolute/path, or another path the server can resolve."

Optional inputs: Label appended with " (optional)" in `text-muted-foreground`. Left empty = omitted from submission.

Default value pre-fill: When the inputs endpoint returns a `default` value, pre-populate the field. Display "(default: {value})" as `text-xs text-muted-foreground` beneath the input.

### "Run" Button in RegistryEntryPage Header

- Placement: next to entry name `h1`, in a `flex items-center justify-between` row matching the "Versions" section header pattern.
- Variant: `default` (primary indigo fill).
- Visible only when `currentMember?.role === 'executor' || currentMember?.role === 'admin'`.
- Hidden (not disabled) for viewers.

### Empty / Loading States

| State | Presentation |
|-------|-------------|
| Inputs loading | Three skeleton rows: `h-4 w-full animate-pulse rounded bg-muted` with label-width skeleton `h-3 w-24` |
| No inputs declared | Informational message inside dialog form area: "This workflow declares no inputs. Click Run Workflow to execute with defaults." |
| Input schema fetch error | `text-muted-foreground text-sm`: "Failed to load workflow inputs. Please close and try again." Submit button disabled. |

## Interaction Contracts

### Dialog Open Flow
1. User clicks "Run" button on RegistryEntryPage.
2. Dialog opens. Version selector mounts. Inputs endpoint called: `GET /projects/{slug}/registry/{name}/inputs?tag={selectedTag}`.
3. While fetching: skeleton rows shown in form area. Submit button disabled.
4. On success: form renders with one field per input, pre-filled with defaults. Submit enabled.
5. On error: error message shown. Submit disabled.

### Version Change
When user changes the selected tag/version in the Select:
- Re-fetch inputs endpoint with new tag.
- Form fields replace (do not merge) with new schema.
- Zod schema rebuilt from new inputs list.
- Any previously entered values are cleared.

### Form Submission
1. react-hook-form `handleSubmit` validates all required fields.
2. Build inputs JSON: include only non-empty fields; omit optional fields left blank.
3. Call `POST /projects/{slug}/workflows` with `{ registry_ref: "{name}:{tag}", inputs: {...} }`.
4. During submit: Submit button shows `Loader2 animate-spin` + "Submitting...". Discard disabled.
5. On success: `toast.success("Run submitted.")` → `navigate(/projects/{slug}/runs/{runId})`. Dialog closes.
6. On error: toast with mapped error message (see Copywriting Contract). Dialog remains open. User can correct and retry.

### Dialog Close / Discard
- Clicking "Discard" or dialog overlay calls `onOpenChange(false)`.
- `form.reset()` called on close — all field values and errors cleared.
- Version selector resets to default tag ("latest" if present, else first).

### Zod Validation Rules
- Required String: `z.string().min(1, '{fieldName} is required')`
- Required Int: `z.coerce.number().int('{fieldName} must be an integer')`
- Required Float: `z.coerce.number('{fieldName} must be a number')`
- Required Boolean: `z.boolean()` (Checkbox — always has value, no "required" check needed)
- Required File: `z.string().min(1, '{fieldName} is required')`
- Required Array/Map/Struct: `z.string().min(1).refine(isValidJSON, '{fieldName} must be valid JSON')`
- Optional variants: wrap with `.optional()` and omit empty string submissions
