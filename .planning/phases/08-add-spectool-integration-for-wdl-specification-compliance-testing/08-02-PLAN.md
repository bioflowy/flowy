  <action>
    1. Create `Makefile` in project root with the following targets:

    ```makefile
    FLOWY_BIN := ./flowy
    SPECTOOL_BIN := $(HOME)/.cargo/bin/spectool
    WDL_SPEC_DIR := /tmp/wdl-spec
    CARGO := $(HOME)/.cargo/bin/cargo

    .PHONY: build spectool test clean

    build: $(FLOWY_BIN)

    $(FLOWY_BIN): $(shell find cmd wdl -name '*.go')
    	go build -o $(FLOWY_BIN) ./cmd/flowy

    test:
    	go test ./... -count=1

    $(SPECTOOL_BIN):
    	@echo "Installing spectool..."
    	@rm -rf /tmp/spectool-src
    	git clone --branch main --depth 1 https://github.com/openwdl/spectool /tmp/spectool-src
    	$(CARGO) install --path /tmp/spectool-src
    	@rm -rf /tmp/spectool-src

    $(WDL_SPEC_DIR):
    	git clone --branch wdl-1.2 --depth 1 https://github.com/openwdl/wdl $(WDL_SPEC_DIR)

    spectool: $(FLOWY_BIN) $(SPECTOOL_BIN) $(WDL_SPEC_DIR)
    	$(SPECTOOL_BIN) test \
    		"$(abspath $(FLOWY_BIN)) run ~{path} --input ~{input}" \
    		--redirect-stdout \
    		-s $(WDL_SPEC_DIR)

    clean:
    	rm -f $(FLOWY_BIN)
    ```

    IMPORTANT: After installing spectool, run `spectool test --help` to verify the exact flag names. The research notes LOW confidence on `--exclude-file`. If that flag does not exist, adapt the Makefile accordingly:
    - If `--exclude` takes a single pattern, use shell expansion: `$(shell cat spectool-exclude.txt | sed '/^#/d' | sed '/^$$/d' | xargs -I{} echo --exclude {})`
    - If neither exists, omit excludes initially and document in the summary.

    Also check: does spectool support `--all-capabilities`? If yes, add it. If not, omit it.

    Note on `~{target}`: The CONTEXT.md template showed `--task ~{target}` but this is problematic because spectool passes workflow names as target too. Two options:
    - Omit `--task ~{target}` from the template entirely. spectool will pass only the WDL file and input. flowy will run the first workflow found (which works for single-workflow test files). For task-only test files, this may not work.
    - Add `--task ~{target}` and make flowy handle both task and workflow names in --task (would require a code change in main.go to fall back to workflow execution).

    Start WITHOUT `--task ~{target}`. Run spectool once and observe failures. If task-targeted tests fail, add the flag and update main.go.

    2. Create `spectool-exclude.txt` with initial patterns. Run spectool with a dry run or initial execution to identify failing test patterns, then populate:

    ```
    # Known unsupported features in flowy v1
    # Remove patterns as features are implemented

    # HTTP/HTTPS imports — v2 roadmap (EXT-01)
    # (exact pattern TBD — populate after first spectool run)

    # Sub-workflow calls — not yet implemented
    # (exact pattern TBD — populate after first spectool run)

    # Object type — WDL 1.2 deprecated, not implemented
    # (exact pattern TBD — populate after first spectool run)
    ```

    After running spectool for the first time, examine the failures. Categorize them:
    - Failures from genuinely unsupported features (HTTP imports, sub-workflows, Object type) -> add to exclude
    - Failures from bugs in flowy -> do NOT exclude, note in summary for future fixing
    - Failures from output format issues -> should have been fixed in Plan 01

    3. Add `flowy` binary and `/tmp/spectool-src` and `/tmp/wdl-spec` to `.gitignore` if not already present. Check first.
