**Daemon struct:**
```go
type Daemon struct {
    cfg      *config.Config
    daemonID string
    client   *http.Client
    wg       sync.WaitGroup
}
```

**New(cfg, daemonID) *Daemon:** Constructor. The daemonID is passed in (generated in main.go as `hostname-PID` per user decision). HTTP client timeout = 35s.

**Run(ctx context.Context) error:**
- Log startup: `daemon starting daemon_id=%s server=%s workers=%d base_dir=%s`
- Start heartbeat goroutine (background, runs for daemon lifetime)
- Start N worker goroutines (N = cfg.Daemon.Workers), each running `workerLoop(ctx)`
- Wait for all workers to finish (via WaitGroup)
- Return nil

**workerLoop(ctx context.Context):**
- Uses a ticker with 5-second interval (short poll, not long poll -- per research recommendation)
- On each tick: call claimTask(ctx). If nil (204), continue. If error, log and continue.
- On successful claim: call executeTask with a SEPARATE context (context.Background()) so SIGTERM does not cancel Docker mid-execution. Track with wg.Add(1).
- On ctx.Done(): return (stops claiming new tasks)

**CRITICAL: Graceful shutdown (Pitfall 6 from research):**
- The poll loop uses the signal-derived ctx -- cancelled on SIGTERM, stops claiming
- Task execution uses context.Background() -- NOT cancelled on SIGTERM
- wg tracks in-flight tasks; Shutdown() calls wg.Wait()
- This ensures in-flight Docker containers complete naturally

**Shutdown():**
- Calls wg.Wait() to block until all in-flight tasks complete

**claimTask(ctx) (*api.TaskClaimResponse, error):**
- POST to {serverURL}/tasks/claim with TaskClaimRequest{DaemonID: d.daemonID}
- Return nil, nil on 204 (no pending tasks)
- Return parsed TaskClaimResponse on 200
- Return error on other status codes or HTTP errors

**executeTask(claim *api.TaskClaimResponse):**
- defer wg.Done()
- Read inputs.json from claim.InputsDir
- Parse WDL file: parser.Parse(claim.WDLPath, nil)
- Find ast.Task by name in doc.Tasks OR doc.Workflows[0].Body (tasks can be defined inside workflows). Search doc.Tasks first, then iterate workflow body for ast.Call nodes matching claim.TaskName.

  Actually, for tasks defined at document level, search doc.Tasks. For tasks called within a workflow, they are still top-level doc.Tasks or imported. The parser puts all task definitions in doc.Tasks. Search doc.Tasks for the matching TaskName.

- Build structDefs from doc.Structs (same pattern as scheduler.structDefs())
- Call task.RunTask(taskCtx, astTask, jsonInputs, task.NewDockerRunner(), claim.OutputsDir, structDefs)
  where taskCtx = context.Background() (not signal ctx)
- On success: serialize outputs via valuesToJSON(), write to {claim.OutputsDir}/outputs.json
- Report result: POST /tasks/{id}/result with COMPLETED or FAILED
- Use context.Background() for the reportResult call (must succeed even after signal)

**sendHeartbeat(ctx) error:**
- POST to {serverURL}/heartbeat with HeartbeatRequest{DaemonID: d.daemonID}
- Return error on failure (caller logs it)

**startHeartbeat(ctx):**
- Background goroutine with ticker at cfg.Daemon.HeartbeatSec interval
- Stops on ctx.Done()

**reportResult(ctx, taskID, state, errMsg):**
- POST to {serverURL}/tasks/{taskID}/result with TaskResultRequest
- Log errors but do not return them (fire-and-forget -- task will be detected as stale if report fails)

**valuesToJSON(outputs map[string]values.Value) (map[string]interface{}, error):**
- Convert WDL values to JSON-compatible Go types
- Handle: StringValue, IntValue, FloatValue, BooleanValue, FileValue, DirectoryValue, NullValue, ArrayValue
- Default: fmt.Sprintf for unknown types

**Key design decisions per CONTEXT.md:**
- daemon_id format: `hostname-PID` (passed in from main.go, NOT uuid per research suggestion -- user locked this)
- Workers default: 1 (configurable via config)
- Graceful shutdown: no hard timeout, wait for Docker to finish (stale detection handles stuck daemons)
- Polling: 5-second short poll interval
