<threat_model>
## Threat Model

### T1: Token forwarded to wrong server (MEDIUM)
- **Attack:** User's credentials.yaml has server A URL, but CLI sends token to server B via --server override
- **Mitigation:** Registry commands use the server URL from credentials file (not a --server flag). The token is bound to the server it was obtained from.
- **Residual risk:** LOW

### T2: WDL file content injection (LOW)
- **Attack:** Malicious WDL file pushed to registry
- **Mitigation:** Server-side validation (already exists). CLI is a thin client; push sends raw file content.
- **Residual risk:** LOW (server responsibility)

### T3: Credential leakage via error messages (MEDIUM)
- **Attack:** Error message includes token value
- **Mitigation:** All error paths print human-readable messages without token content. ErrUnauthorized/ErrForbidden sentinels carry no token data.
- **Residual risk:** LOW
</threat_model>
