## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` (`--background`, white) | Page background, card background, member table background |
| Secondary (30%) | `oklch(0.968 0.007 247.896)` (`--sidebar`, slate-50) | Sidebar background, project card hover state, table header row background |
| Accent (10%) | `oklch(0.488 0.243 264.376)` (`--primary`, blue-ish slate) | "Create Project" button, "Add Member" dialog submit, "Create" submit on CreateProjectPage |
| Destructive | `oklch(0.637 0.237 25.331)` (`--destructive`, red-500) | "Delete Project" confirmation button, "Remove" member confirmation button, inline form validation errors |

Accent reserved for: the "Create Project" button on the projects list page, the "Create" submit button on CreateProjectPage, the "Add Member" submit button inside AddMemberDialog. No other elements use the accent/primary color.

Role badge colors (from shadcn/ui Badge component variants):
- Role "admin": `variant="default"` — filled primary background, primary-foreground text
- Role "executor": `variant="secondary"` — muted background, muted-foreground text
- Role "viewer": `variant="outline"` — neutral border, foreground text

Rationale: admin is the highest-privilege role, warranting the primary/accent color to signal elevated access. Executor gets secondary emphasis. Viewer gets neutral outline. Distinguished by both color and text content (never color alone).

Source: Phase 27 UI-SPEC color contract carried forward. Badge color mapping from CONTEXT.md Discretion list (exact badge colors for roles).

## Screen Inventory

Phase 28 introduces three new pages and one dialog modal. It also modifies the sidebar significantly.

### Screen 1: Projects Page (`/projects`)

Default landing page after login. Card grid showing projects the current user belongs to.

```
+-----------------------------------------------------------+
|  Sidebar                |  Projects           [Create Project]  (admin only)
|  [Select project...]    |  -------------------------------------------
|                         |  +------------------+  +------------------+
|  (no project nav yet)   |  |  my-project      |  |  data-pipeline   |
|                         |  |  my-project      |  |  data-pipeline   |
|  > Users (admin only)   |  |  A workflow...   |  |  Runs daily...   |
|                         |  |  3 members       |  |  5 members       |
|                         |  +------------------+  +------------------+
|                         |
|                         |  (empty state if no projects)
+-----------------------------------------------------------+
```

- Page heading: "Projects" — Heading (20px / semibold)
- "Create Project" button: positioned to the right of the page heading (flex row, justify-between), `variant="default"` (accent/primary). Only rendered when `authStore.role === 'admin'`.
- Grid: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6` using shadcn/ui `<Card>` components
- Each project card:
  - Card title: project `slug` — Heading (20px / semibold) inside `<CardHeader>`
  - Description: first 2 lines max (`line-clamp-2`), `--muted-foreground` color — Body (14px / regular / 1.5)
  - Member count: "(N members)" — Body (14px / regular / 1.5), muted-foreground. Shown below description.
  - NOTE: `ProjectResponse` has no `member_count` field. Member count requires a separate `GET /projects/{slug}/members` call per card. Omit member count from card display to avoid N+1 requests. Show only slug + description snippet.
  - Card hover: `cursor-pointer`, subtle background shift to `--sidebar` color (slate-50)
  - Card click: calls `setActiveProject(slug)` then navigates to `/projects/{slug}`
- Loading state: 3 skeleton cards (gray rectangles) matching card dimensions, rendered during `useProjects()` isLoading

### Empty State (Projects Page)

Displayed when `useProjects()` returns empty array.

```
+-------------------------------+
|  No projects yet.             |
|  Create one to get started.   |
|  (admin) [Create Project]     |
+-------------------------------+
```

Centered in page content area:
- Heading: "No projects yet." — Heading (20px / semibold)
- Body: "You are not a member of any projects." — Body (14px / regular / 1.5), muted-foreground
- For admin: "Create Project" button below body copy, `variant="default"`
- For non-admin: no button (only admin can create projects)

### Screen 2: Create Project Page (`/projects/new`)

Full page (not a dialog). Admin-only route (non-admins never see "Create Project" button, so they never navigate here).

```
+-----------------------------------------------------------+
|  Sidebar                |  Create Project
|                         |  -------------------------------------------
|                         |  Name *                    [              ]
|                         |  Slug *                    [my-project    ]
|                         |                            slug is auto-generated
|                         |  Description               [              ]
|                         |                            [              ]
|                         |
|                         |  [Cancel]         [Create]
+-----------------------------------------------------------+
```

- Page heading: "Create Project" — Heading (20px / semibold)
- Form fields (react-hook-form + zod):
  - **Name** (required): `<Label>` "Name" + `<Input>` (type="text", placeholder="My Project"). Drives slug auto-generation on change. This field is frontend-only — the backend `CreateProjectRequest` has no `name` field.
  - **Slug** (required): `<Label>` "Slug" + `<Input>` (type="text", placeholder="my-project"). Auto-populated from name, manually overridable. Hint text below: "Lowercase letters, numbers, and hyphens only." — Label (12px / regular / 1.4), muted-foreground.
  - **Description** (optional): `<Label>` "Description" + `<Textarea>` (3 rows). Placeholder: "A brief description of this project."
- Slug auto-generation: fires on every name keystroke if the slug field has not been manually edited. Once the user edits slug directly, auto-generation stops.
- Zod schema: slug must match `/^[a-z0-9]([a-z0-9-]{0,62}[a-z0-9])?$/`. Error: "Lowercase alphanumeric and hyphens only, no leading/trailing hyphens."
- "Create" submit button: `variant="default"` (accent/primary). Loading state: disabled + `<Loader2 animate-spin>`, text "Creating..."
- "Cancel" button: `variant="ghost"`. Navigates back to `/projects`.
- On success: navigate to `/projects/{slug}`, call `setActiveProject(slug)`
- On API error: inline error below form — Body (14px / regular / 1.5), destructive color

### Screen 3: Project Detail Page (`/projects/:slug`)

Single scrollable page with two sections: project info header + member list table.

```
+-----------------------------------------------------------+
|  Sidebar                |  my-project
|  [my-project v]         |  slug: my-project
|  > Registry             |  A workflow for processing genomic data.
|  > Runs                 |
|  > Members              |  [Edit Description]  [Delete Project]  (project admin only)
|                         |
|                         |  Members               [Add Member]  (project admin only)
|                         |  -------------------------------------------
|                         |  Username   Role         Joined      Actions
|                         |  -------------------------------------------
|                         |  alice      [admin v]    Mar 15      (disabled for self)
|                         |  bob        [executor v] Mar 16      ...
|                         |  carol      [viewer v]   Mar 17      ...
+-----------------------------------------------------------+
```

- Page heading: project `slug` — Heading (20px / semibold)
- Slug label below heading: "slug: {slug}" — Label (12px / regular / 1.4), muted-foreground
- Description: Body (14px / regular / 1.5). Empty description shows muted italic "No description." text.
- "Edit Description" button: `variant="outline"`. Visible only to project admins (`isProjectAdmin === true`). Opens Edit Description dialog.
- "Delete Project" button: `variant="destructive"` outline style. Visible only to project admins. Opens Delete Project confirmation dialog.
- **Project admin detection**: Derived from members list — `currentMember?.role === 'admin'` where `currentMember = members?.find(m => m.username === authStore.username)`. NOT based on global `authStore.role`.

#### Member Table

- Section heading: "Members" — Heading (20px / semibold), positioned left with "Add Member" button right
- "Add Member" button: `variant="default"` (accent/primary). Visible only to project admins. Opens AddMemberDialog.
- Table: shadcn/ui `<Table>`
- Columns: Username, Role, Joined, Actions (empty header)
  - Username: Body (14px / regular / 1.5)
  - Role: inline `<Select>` component (width `w-32`), options: admin / executor / viewer. Immediately calls `PUT /projects/{slug}/members/{username}` on change. Shows success toast "Role updated." On error: toast "Something went wrong. Please try again."
  - Joined: formatted date "Mar 15, 2026" — Body (14px / regular / 1.5)
  - Actions: three-dot `<DropdownMenu>` with single item "Remove" (destructive text color, `text-destructive`). Opens Remove confirmation dialog.
- Self-protection: for the current logged-in user's row, the Role Select is `disabled` and the three-dot dropdown is NOT rendered (nil).
- Loading state: 3 skeleton rows while `useProjectMembers()` is loading.

## Accessibility Requirements

All interactive elements must meet WCAG 2.1 AA:

- Every `<Input>` and `<Textarea>` has an associated `<Label>` connected via `htmlFor` / `id` — shadcn/ui `<Form>` handles this
- Error messages are associated with their input via `aria-describedby` — shadcn/ui `<FormMessage>` handles this
- `<AlertDialog>` traps focus and requires explicit user action — Radix UI AlertDialog handles this
- `<DropdownMenu>` supports keyboard navigation (arrow keys, Enter, Escape) — Radix UI handles this
- `<Select>` supports keyboard navigation — Radix UI handles this
- Table uses semantic `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` elements — shadcn/ui Table renders these
- Role badges distinguished by text content, not color alone — all badges include readable role labels
- Destructive actions (Delete Project, Remove Member) require explicit confirmation dialog before execution
- Self-protection rows: disabled Role `<Select>` must include `aria-label="You cannot change your own role"` or `<Tooltip>` with explanation
