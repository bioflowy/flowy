<feature>
  <name>Core type checker: two-pass resolution, Kahn toposort, scatter/if promotion</name>
  <files>wdl/checker/checker.go</files>
  <behavior>
    Check(doc *ast.Document) (TypeEnv, []error):

    Pass 1 — collectDecls for each task and workflow:
    - For each task: create a per-task Scope; register all Inputs, Decls, Outputs with their declared types (decl.Type) into the scope; process any Scatter/Conditional in workflow.Body with promotion (see below)
    - For each workflow: create a per-workflow Scope; register Inputs; walk Body nodes — Decl nodes register directly; Scatter nodes recursively collect inner declarations into a temp inner scope, then register each into the outer scope wrapped with arrayize(); Conditional nodes do the same wrapped with optionalize()
    - Nested scatter-inside-if: when a Scatter is inside a Conditional, each inner decl gets optionalize() applied by the Conditional, then arrayize() applied by the Scatter (or vice-versa depending on nesting order) — the rule is: apply the innermost promotion first, then the outer promotion wraps the result

    Pass 2 — validateDecls for each task and workflow:
    - Run toposort (Kahn's algorithm) on the dependency graph for the scope
    - Build dependency graph: for each Decl, walk its Expr AST to find all IdentExpr names that appear in the same scope; those are edges (decl.Name depends on ident.Name)
    - If toposort fails (cycle), append a TypeError with the cycle description and continue to next scope (do not abort all validation)
    - For each Decl (in topological order): if decl.Expr is a literal (BoolLit, IntLit, FloatLit, NullLit, StringExpr), derive the literal's type (BooleanType, IntType, FloatType, AnyType{Optional:true}, StringType respectively); check that the literal type equals decl.Type or Coerces(literalType, decl.Type); if not, append TypeError{Pos: decl.Pos, Message: "..."}
    - For IdentExpr initializers: look up the ident's type in scope; check Coerces(identType, decl.Type)
    - For all other Expr types (BinaryExpr, ApplyExpr, etc.): skip type validation (deferred to Phase 4); do not produce errors for complex expressions

    toposort(nodes []string, edges map[string][]string) ([]string, error):
    - Implement Kahn's algorithm (30 lines): compute in-degrees, iteratively remove zero-in-degree nodes, collect order; if len(order) != len(nodes), remaining nodes form a cycle → return error describing which names are involved

    collectIdents(expr ast.Expr) []string:
    - Walk expression tree, collect all IdentExpr.Name values; used for dependency edge extraction

    TypeError messages:
    - Cycle: fmt.Sprintf("circular dependency among declarations: %v", cycleNames)
    - Type mismatch: fmt.Sprintf("cannot use %s where %s is expected", from.TypeName(), to.TypeName())
    - Undefined name: fmt.Sprintf("undefined name %q", name)
  </behavior>
