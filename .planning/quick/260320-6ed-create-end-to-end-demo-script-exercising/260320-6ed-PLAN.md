**scripts/demo-v1.3.sh** — A bash script (chmod +x) structured as follows:

1. **Preamble**: set -euo pipefail. Define SCRIPT_DIR, PROJECT_ROOT (parent of scripts/), PORT=8199
   (avoid conflict with default 8124 and S3 test 8125), CONFIG=/tmp/flowy-demo-v1.3.yaml,
   DATA_DIR=/tmp/flowy-demo-v1.3-data, ADMIN_USER=demoadmin, ADMIN_PASS=demopass123,
   JWT_SECRET=demo-secret-for-testing, DAEMON_TOKEN=demo-daemon-token.
   Define BASE_URL=http://localhost:$PORT.

2. **Cleanup trap**: trap function that kills server+daemon PIDs (from PID files in DATA_DIR),
   removes DATA_DIR and CONFIG. Use `trap cleanup EXIT`.

3. **Build**: Run `make build` from PROJECT_ROOT.

4. **Generate config**: Write YAML to $CONFIG:
   ```yaml
   base_dir: $DATA_DIR
   server:
     listen_addr: ":$PORT"
   daemon:
     server_url: "http://localhost:$PORT"
     workers: 2
   auth:
     enabled: true
     jwt_secret: $JWT_SECRET
     daemon_token: $DAEMON_TOKEN
   ```

5. **Init admin**: Run `$PROJECT_ROOT/flowy-server -config $CONFIG --init-admin --username $ADMIN_USER --password $ADMIN_PASS`.

6. **Start server**: Run `$PROJECT_ROOT/flowy-server -config $CONFIG` in background, save PID.
   Wait loop (up to 10s) polling `curl -sf $BASE_URL/health` or similar endpoint. Use
   `curl -sf -o /dev/null $BASE_URL/runs` as the health check (the /runs endpoint returns 401
   when auth enabled, but the daemon routes should still be reachable — check for any non-connection-error
   response). Actually, since auth is enabled, use: `curl -s -o /dev/null -w '%{http_code}' $BASE_URL/daemon/tasks/claim` which should return 401 (confirming server is up). Just check that curl gets ANY HTTP response.

7. **Start daemon**: Run `$PROJECT_ROOT/flowy-daemon -config $CONFIG --workers 2` in background, save PID. Sleep 1s.

8. **Section headers**: Print colored section headers for each feature area using echo with ANSI codes.

9. **Feature 1 — Authentication**:
   - `POST /auth/login` with admin credentials -> extract TOKEN from JSON response using jq.
   - Set `AUTH="Authorization: Bearer $TOKEN"`.
   - Verify token works: `GET /users` with auth header -> should return 200.

10. **Feature 2 — Projects & RBAC**:
    - `POST /projects` with `{"name":"Demo Project","slug":"demo"}` -> verify 201.
    - `POST /users` (as admin) to create a second user (executor1/exec-pass) -> verify 201.
    - `POST /projects/demo/members` to add executor1 as executor role -> verify 200/201.
    - `GET /projects/demo` -> verify project details returned.

11. **Feature 3 — WDL Registry**:
    - Read the WDL file content, POST it to `/projects/demo/registry` with `{"name":"hello","kind":"task","source":"<wdl content>"}` -> verify 201. Extract digest from response.
    - `POST /projects/demo/registry/hello/tags` with `{"tag":"v1","digest":"$DIGEST"}` -> verify 200/201.
    - `GET /projects/demo/registry/hello/versions` -> verify lists the pushed version.
    - `GET /projects/demo/registry/hello?ref=hello:v1` -> verify can pull by tag.

12. **Feature 4 — Registry-Based Execution**:
    - `POST /projects/demo/tasks/run` with `{"registry_ref":"hello:v1","inputs":{"name":"Demo"}}` -> extract run ID.
    - Poll `GET /projects/demo/runs/$RUN_ID/status` until terminal state (Complete/Failed), max 60s.
    - `GET /projects/demo/runs/$RUN_ID/outputs` -> verify outputs contain greeting.

13. **Feature 5 — Provenance Tracking**:
    - `GET /projects/demo/provenance` -> verify list includes the run.
    - `GET /projects/demo/provenance/$RUN_ID` -> verify detail includes registry ref info.

14. **Summary**: Print a summary of all features exercised with pass/fail indicators.

For every curl call, use a helper function like:
```bash
api() {
  local method=$1 path=$2; shift 2
  local response
  response=$(curl -sf -w '\n%{http_code}' -X "$method" -H "Content-Type: application/json" -H "$AUTH" "$@" "$BASE_URL$path")
  local http_code=$(echo "$response" | tail -1)
  local body=$(echo "$response" | sed '$d')
  echo "$body"
  # Optionally check status code
}
```

Use `set -e` so any failed curl aborts the script. Print the step being executed before each API call.
Do NOT use -f flag on curl calls that might return non-2xx legitimately (like polling status).
Instead, check http_code explicitly for error handling.

The script should be well-commented, explaining what each section tests.
