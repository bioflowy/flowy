# Requirements: flowy v2.1 Job Execution & Registry CLI

**Defined:** 2026-04-07
**Core Value:** WDL 1.2で記述されたワークフローをDockerコンテナ上で正確に実行できること

## v2.1 Requirements

Requirements for Job Execution & Registry CLI milestone. Each maps to roadmap phases.

### CLI Authentication

- [ ] **CLI-01**: User can log in via `flowy login` and JWT token is saved to credentials file (~/.flowy/credentials.yaml)
- [ ] **CLI-02**: All authenticated CLI commands automatically load saved token from credentials file

### CLI Registry

- [ ] **REG-CLI-01**: User can push a WDL file to registry via `flowy registry push --project <slug> --name <name> <file.wdl>`
- [ ] **REG-CLI-02**: User can list registry entries via `flowy registry list --project <slug>`
- [ ] **REG-CLI-03**: User can pull WDL source via `flowy registry pull --project <slug> --name <name> [--tag <tag>]`
- [ ] **REG-CLI-04**: User can manage tags via `flowy registry tag` and `flowy registry delete-tag`
- [ ] **REG-CLI-05**: Admin can delete a registry entry via `flowy registry delete --project <slug> --name <name>`

### UI Registry Upload

- [ ] **REG-UI-01**: User can upload a WDL file from browser to push to registry (FileReader + existing push API)

### UI Workflow Execution

- [ ] **EXEC-01**: User can select a workflow from registry to execute (dialog with entry/version selection)
- [ ] **EXEC-02**: User can input workflow parameters via dynamically generated form (String, Int, Float, Boolean, File with specialized controls; Array/Map/Struct via JSON textarea)
- [ ] **EXEC-03**: User can submit workflow execution from the UI and see confirmation
- [ ] **EXEC-04**: User can monitor running workflow status via poll-based updates (auto-stop on terminal state)
- [ ] **EXEC-05**: User can view execution results and output files after completion (reuses Phase 30 output viewer)

### API Foundation

- [ ] **API-01**: Server provides input schema endpoint for registry entries (GET /projects/{slug}/registry/{name}/inputs)
- [ ] **API-02**: Server provides file upload endpoint for File-typed workflow inputs

## v2.2+ Requirements (Deferred)

- Dynamic form for compound types (Array, Map, Struct) with dedicated UI widgets
- WebSocket/SSE for real-time status updates
- Workflow execution history with re-run capability
- Batch execution (multiple workflows)

## Out of Scope

- WDL input parsing in browser (server-side via existing parser)
- Presigned S3 URLs for file upload (backend proxy approach)
- OAuth2/LDAP/SSO for CLI authentication
