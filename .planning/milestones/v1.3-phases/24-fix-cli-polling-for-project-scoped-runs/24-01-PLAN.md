<objective>
Fix CLI polling and output retrieval for project-scoped runs. After submitting a workflow via registry reference (which uses project-scoped routes), the CLI currently calls `c.Status()` and `c.Outputs()` which hit `/workflows/{id}/status` and `/workflows/{id}/outputs` — routes that do not exist in auth-enabled mode. This plan adds `StatusInProject` and `OutputsInProject` client methods and updates `pollUntilDone` and `runRun` to use them when a project slug is known.

Purpose: Close the EXEC-01 gap so the full E2E flow (login -> push -> submit by registry ref -> poll -> outputs) works end-to-end with auth enabled.
Output: Updated client library and CLI with project-scoped polling, plus tests.
</objective>
