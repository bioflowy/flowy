# Milestone v2.2: Managed File Library

**Status:** ✅ SHIPPED 2026-04-19
**Phases:** 37-40
**Total Plans:** 8

## Overview

v2.2 introduced a project-scoped managed file library so browser users can import files, browse registered `File` and `Directory` assets, and select managed files directly when launching workflows. The milestone also closed the loop between workflow completion and file discovery by auto-registering declared workflow outputs as managed files and propagating `parameter_meta.type` annotations into both stored managed-file metadata and browser-side workflow input filtering.

## Phases

### Phase 37: Backend Foundation

**Goal**: The data layer and storage interfaces needed to persist and measure managed files are in place so later phases can build on a stable foundation.
**Depends on**: Phase 36
**Plans**: 2 plans

Plans:

- [x] 37-01: ManagedFile model, Store CRUD, and CompleteRun transaction
- [x] 37-02: Backend.Stat and S3APIClient.HeadObject

**Details:**
Added the `managed_files` SQLite table, `ManagedFile` store model, CRUD store methods, and `CompleteRun(...)` transaction support. Extended the storage backend abstraction with `Backend.Stat(...)`, plus `LocalBackend.Stat(...)` and `S3Backend.Stat(...)`, so imported files and auto-registered outputs can record byte size consistently across local and S3-backed storage.

### Phase 38: File Library REST API

**Goal**: Users and the system can list, import, and delete managed files in a project through a guarded REST API.
**Depends on**: Phase 37
**Plans**: 2 plans

Plans:

- [x] 38-01: API types, route wiring, GET/DELETE handlers
- [x] 38-02: POST import handler for browser upload, S3 URI, and local server path

**Details:**
Added `GET /projects/{slug}/files`, `POST /projects/{slug}/files`, and `DELETE /projects/{slug}/files/{id}` with RBAC gating. Browser uploads reuse backend streaming, S3 imports validate existence via `Stat`, and server-local imports are constrained to `Config.ImportRoot` to prevent path traversal outside the approved import root.

### Phase 39: Workflow Completion Hook and Type Annotation

**Goal**: Completed workflow runs automatically populate the file library and WDL type annotations flow through to managed-file metadata.
**Depends on**: Phase 37
**Plans**: 2 plans

Plans:

- [x] 39-01: Atomic workflow completion registration
- [x] 39-02: `parameter_meta.type` propagation for managed files and registry inputs

**Details:**
Reworked workflow completion so run state transition and managed-file registration happen through a single `CompleteRun(...)` transaction. Added declared-output walking for `File`, `Directory`, `Array[File]`, and `Array[Directory]`, deduplicating repeated paths inside one completion event. Added defensive `parameterMetaType(...)` handling so browser input introspection can expose `file_type` without breaking existing WDL files that use unrelated `parameter_meta` keys.

### Phase 40: UI — Files Tab and File Picker

**Goal**: Users can manage their project's file library from the browser and select managed files directly when launching workflows.
**Depends on**: Phase 38, Phase 39
**Plans**: 2 plans

Plans:

- [x] 40-01: Files tab, managed-file hooks, and import dialog
- [x] 40-02: Managed-file picker in `RunWorkflowDialog`

**Details:**
Added a `Files` tab in `ProjectDetailPage`, wired managed-file list/import/delete hooks, and introduced `ImportFileDialog` for browser, S3, and server-path imports. Updated `RunWorkflowDialog` so `File` inputs show a managed-file picker with type-based filtering from `parameter_meta.type`, while keeping a manual path fallback for unmanaged or externally staged paths.

## Milestone Summary

**Key Decisions:**

- Managed files are project-scoped records; deleting a managed-file row never deletes the underlying storage object.
- Workflow completion uses a single `CompleteRun(...)` transaction so output registration and run state changes cannot drift.
- `parameter_meta.type` is treated as a defensive optional annotation: malformed metadata is ignored rather than causing runtime failures.
- The file picker keeps manual path entry alongside managed-file selection so external `s3://` or absolute server paths remain usable.
- Registry input lookup accepts digest queries directly and registry push auto-assigns `latest` to improve browser resilience when immutable digests are selected.

**Issues Resolved:**

- Added the missing project-scoped managed-file REST surface for list/import/delete operations.
- Eliminated the gap between workflow completion and file-library discoverability by auto-registering output files.
- Replaced plain text-only File inputs in the browser with a guided managed-file picker.
- Fixed digest-based workflow input introspection so browser views no longer 404 when the selected version is represented by `sha256:...`.

**Issues Deferred:**

- Shell-style label-template evaluation in `parameter_meta` remains deferred to a later milestone.
- Files tab search/filter, provenance badges, and pagination remain future polish work.
- A formal `v2.2` milestone audit file was not generated; completion proceeded after manual verification and targeted automated test runs.

**Technical Debt Incurred:**

- ESLint v9 remains blocked until the repository adopts an `eslint.config.js`.
- Managed-file labeling still defaults to path/filename because label-template evaluation is not implemented yet.
