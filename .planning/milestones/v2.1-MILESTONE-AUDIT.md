### Non-Blocking Integration Gap

**API-02: uploads endpoint unused from browser**

`POST /projects/{slug}/uploads` was built in Phase 32 as a prerequisite for browser File-typed input upload. Phase 36 chose to implement File-typed inputs as tooltip-documented text fields (requiring users to supply server-accessible paths such as `s3://...` or `/absolute/path`). The endpoint is production-ready and tested but has zero browser callers.

This is consistent with ADR 0001 (File inputs are path-entry strings) and ROADMAP SC4 ("File-typed inputs display a placeholder and tooltip explaining that server-accessible paths are required"). It is a feature shortfall for the browser upload UX, not a broken flow.

- **File:** `internal/server/handlers_uploads.go` (server); `web/src/features/registry/RunWorkflowDialog.tsx` lines 383-387 (browser)
- **Deferred to:** v2.2+ ("Presigned S3 URLs for file upload" — already listed in REQUIREMENTS.md Out of Scope)
