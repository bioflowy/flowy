### Partial Requirement: EXEC-01

**EXEC-01:** Executor can submit a run by registry reference

- **Server-side:** Fully working. `resolveRegistryRefFull` resolves WDL, run starts, `handleClaim` re-resolves by digest for daemon.
- **CLI-side:** `flowy run name:tag --project slug` correctly submits via `SubmitToProject`. But `pollUntilDone` then calls `c.Status()` → `GET /workflows/{id}/status` which **does not exist** in auth-enabled mode (only `/projects/{slug}/runs/{id}/status` is registered).
- **Impact:** Registry-based `flowy run` cannot poll to completion in auth-enabled mode. The run executes but CLI hangs/errors.
- **Fix:** Add `StatusInProject(ctx, slug, runID)` and `OutputsInProject(ctx, slug, runID)` to `internal/client/client.go`, and update `pollUntilDone` in `cmd/flowy/main.go` to use them when `projectSlug` is known.
