Use `.minio.cid` (container ID file) instead of PID file, since MinIO runs as a Docker container (use `docker run --cidfile`). This is cleaner than capturing a PID.

3. Add `integration` target:
```makefile
integration:
	go test -tags integration -timeout 2m -count=1 ./internal/integration/...
```

4. Add `spectool-s3` target following the existing `spectool` pattern closely:
   a. Prerequisites: `$(FLOWY_BIN) $(SERVER_BIN) $(DAEMON_BIN) $(SPECTOOL_BIN) $(WDL_SPEC_DIR)`
   b. Clean up stale data: `docker run --rm -v $(abspath .)/flowy-data-s3:/data alpine sh -c "rm -rf /data/*" 2>/dev/null || true` then `rm -rf ./flowy-data-s3 && mkdir -p ./flowy-data-s3`
   c. Stop any leftover MinIO container: `docker rm -f $$(cat $(MINIO_CID)) 2>/dev/null; rm -f $(MINIO_CID)`
   d. Start MinIO with `docker run --rm -d --cidfile $(MINIO_CID) -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin -p $(MINIO_PORT):9000 $(MINIO_IMAGE) server /data`
   e. Wait for MinIO readiness with curl loop on `http://localhost:$(MINIO_PORT)/minio/health/live` (same pattern as server readiness check, 10 iterations with 1s sleep)
   f. Create bucket: `AWS_ACCESS_KEY_ID=minioadmin AWS_SECRET_ACCESS_KEY=minioadmin aws --endpoint-url http://localhost:$(MINIO_PORT) s3 mb s3://$(TEST_BUCKET) --region us-east-1` (if aws CLI is available, otherwise use curl PUT to create bucket)
   g. Generate temporary config.yaml at `$(S3_CONFIG)` using printf with S3 settings. Use port $(S3_PORT) for server listen_addr to avoid conflict with regular spectool (port 8124). Include `base_dir: ./flowy-data-s3`.
   h. Export `AWS_ACCESS_KEY_ID=minioadmin` and `AWS_SECRET_ACCESS_KEY=minioadmin` for server and daemon processes.
   i. Start server: `AWS_ACCESS_KEY_ID=minioadmin AWS_SECRET_ACCESS_KEY=minioadmin $(SERVER_BIN) -c $(S3_CONFIG) & echo $$! > $(SERVER_PID)`
   j. Wait for server readiness on port $(S3_PORT): curl loop on `http://localhost:$(S3_PORT)/runs`
   k. Start daemon: `AWS_ACCESS_KEY_ID=minioadmin AWS_SECRET_ACCESS_KEY=minioadmin $(DAEMON_BIN) -c $(S3_CONFIG) --workers 4 & echo $$! > $(DAEMON_PID)`
   l. Sleep 1 second for daemon startup.
   m. Run spectool with the same arguments as regular spectool target, but use `$(abspath $(FLOWY_BIN)) run -c $(S3_CONFIG) --input ~{input} ~{path}` so flowy uses S3 config. Capture exit code.
   n. Cleanup: kill daemon PID, kill server PID, stop MinIO container (`docker rm -f $$(cat $(MINIO_CID))`), remove PID/CID files, remove temp config. Exit with spectool exit code.

IMPORTANT per RESEARCH.md:
- Use port 8125 (not 8124) so spectool-s3 can run simultaneously with regular spectool
- Export AWS credentials as env vars before starting server/daemon (config.yaml does not support credentials by design)
- Use `docker rm -f` with CID file for reliable MinIO cleanup (Pitfall 5)
