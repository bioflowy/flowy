## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Weights declared: 400 (regular) for body and label, 600 (semibold) for heading and display. Exactly 4 sizes, exactly 2 weights.

Application in Phase 27:
- Page heading ("Users"): Heading -- 20px / semibold / 1.2
- Table column headers (Username, Role, Status, Created): Label -- 12px / regular / 1.4, muted-foreground
- Table cell text (usernames, dates): Body -- 14px / regular / 1.5
- Badge text (role, status): Label -- 12px / regular / 1.4
- Dialog titles ("Create User", "Deactivate {username}?", "Reset Password"): Heading -- 20px / semibold / 1.2
- Form field labels in dialogs: Label -- 12px / regular / 1.4
- Input field text in dialogs: Body -- 14px / regular / 1.5
- Inline validation errors: Label -- 12px / regular / 1.4, destructive color
- Dropdown menu items: Body -- 14px / regular / 1.5

Source: Phase 26 UI-SPEC typography contract. No changes.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` (`--background`, white) | Page background, table background |
| Secondary (30%) | `oklch(0.968 0.007 247.896)` (`--sidebar`, slate-50) | Sidebar background, table header row background |
| Accent (10%) | `oklch(0.488 0.243 264.376)` (`--primary`, slate-700) | "Create User" button, dialog submit buttons |
| Destructive | `oklch(0.637 0.237 25.331)` (`--destructive`, red-500) | "Deactivate" confirmation button, inline form validation errors |

Accent reserved for: the "Create User" primary button, the "Create" submit button inside Create User dialog, the "Reset password" submit button inside Reset Password dialog. No other elements use the accent/primary color.

Badge colors (from shadcn/ui Badge component variants):
- Role badges (admin, executor, viewer): `variant="outline"` -- neutral border, foreground text. Distinguished by text content, not color.
- Status "Active": `variant="default"` -- filled primary background, primary-foreground text
- Status "Inactive": `variant="secondary"` -- muted background, muted-foreground text

Source: Phase 26 UI-SPEC color contract carried forward. Badge color recommendations from RESEARCH.md Discretion Recommendations.

## Screen Inventory

Phase 27 introduces one new screen, three dialog modals, and modifies the sidebar.

### Screen 1: Users Page (`/users`)

Page within AppShell. Admin-only route. Contains user table with action dropdown per row.

```
+-----------------------------------------------------------+
|  Sidebar               |  Users                    [Create User]
|                         |  -------------------------------------------
|  (nav items)            |  Username    Role      Status    Created
|                         |  -------------------------------------------
|  > Users (admin only)   |  alice       admin     Active    2026-03-15
|                         |  bob         executor  Active    2026-03-16
|                         |  carol       viewer    Inactive  2026-03-17  ...
|                         |  dave        viewer    Active    2026-03-18  ...
|                         |
|                         |  (empty state if no users)
+-----------------------------------------------------------+
```

- Page heading: "Users" -- Heading (20px / semibold)
- "Create User" button: positioned to the right of the page heading (flex row, justify-between), variant="default" (accent/primary). This is the primary visual focal point alongside the page heading.
- Table: shadcn/ui `<Table>` component (not @tanstack/react-table -- user count is small)
- Table header: `<TableHeader>` with columns: Username, Role, Status, Created, Actions (empty header, `w-[50px]`)
- Table rows: `<TableRow>` for each user
  - Username cell: Body text (14px / regular)
  - Role cell: `<Badge variant="outline">` showing global_role (admin, executor, viewer)
  - Status cell: `<Badge variant="default">` for Active, `<Badge variant="secondary">` for Inactive
  - Created cell: formatted date string (e.g., "Mar 15, 2026")
  - Actions cell: three-dot `<DropdownMenu>` trigger (lucide `<MoreHorizontal>` icon, 16px)
- Actions dropdown contents (conditional on user state):
  - For active users: "Deactivate" (destructive text color), "Reset Password"
  - For inactive users: "Reactivate", "Reset Password"
  - For current logged-in admin's own row: hide the entire dropdown (prevent self-deactivation)
- Self-identification: compare `user.username` with `authStore.username` (both unique, no need for userId)
- No pagination: show all users in a single table (admin tool, small user counts expected)

### Loading State

- Show skeleton rows (3-4 rows of gray placeholder blocks) while `useUsers()` query is loading
- Skeleton uses `--muted` background with rounded rectangles matching column widths

### Empty State

- Shown inside `<TableBody>` when API returns zero users
- Single `<TableRow>` spanning all columns, centered text
- Copy: "No users found." -- Body (14px / regular / muted-foreground)

### Modal 1: Create User Dialog

Triggered by "Create User" button. Uses shadcn/ui `<Dialog>`.

```
+-------------------------------+
|  Create User              [x] |
|  ---                          |
|  Username *          [      ] |
|  Password *          [      ] |
|  Role *              [viewer] |
|  Display Name        [      ] |
|  Email               [      ] |
|                               |
|  [Cancel]        [Create]     |
+-------------------------------+
```

- Dialog title: "Create User" -- Heading (20px / semibold)
- Form: react-hook-form + zod schema
- Required fields:
  - Username: `<Label>` + `<Input>` (type="text", autocomplete="off")
  - Password: `<Label>` + `<Input>` (type="password", autocomplete="new-password"), min 8 chars
  - Role: `<Label>` + shadcn/ui `<Select>` with options: admin, executor, viewer. Default: "viewer"
- Optional fields:
  - Display Name: `<Label>` + `<Input>` (type="text")
  - Email: `<Label>` + `<Input>` (type="email")
- Submit button: "Create" -- variant="default" (accent/primary)
- Cancel button: "Cancel" -- variant="ghost"
- On success: sonner toast "User created.", dialog closes, table auto-refreshes via React Query invalidation
- On error: inline error message below form (API error text)

### Modal 2: Deactivate Confirmation Dialog

Triggered from row dropdown "Deactivate" action. Uses shadcn/ui `<AlertDialog>`.

```
+------------------------------------+
|  Deactivate alice?                 |
|                                    |
|  They will no longer be able to    |
|  log in.                           |
|                                    |
|  [Cancel]        [Deactivate]      |
+------------------------------------+
```

- Dialog title: "Deactivate {username}?" -- Heading (20px / semibold)
- Description: "They will no longer be able to log in." -- Body (14px / regular / muted-foreground)
- Confirm button: "Deactivate" -- variant="destructive" (red background)
- Cancel button: "Cancel" -- variant="outline"
- On success: sonner toast "{username} deactivated.", dialog closes, table refreshes
- On error: sonner toast with error message (dialog stays open)

### Modal 3: Reset Password Dialog

Triggered from row dropdown "Reset Password" action. Uses shadcn/ui `<Dialog>`.

```
+-------------------------------+
|  Reset Password           [x] |
|  ---                          |
|  Resetting password for alice |
|                               |
|  New password        [      ] |
|  Confirm password    [      ] |
|                               |
|  [Cancel]     [Reset password]|
+-------------------------------+
```

- Dialog title: "Reset Password" -- Heading (20px / semibold)
- Description: "Resetting password for {username}" -- Body (14px / regular / muted-foreground)
- New password field: `<Label>` + `<Input>` (type="password", autocomplete="new-password"), min 8 chars
- Confirm password field: `<Label>` + `<Input>` (type="password", autocomplete="new-password")
- Zod validation: passwords must match, min 8 chars (same schema pattern as Phase 26 ChangePasswordDialog)
- Submit button: "Reset password" -- variant="default" (accent/primary)
- Cancel button: "Cancel" -- variant="ghost"
- On success: sonner toast "Password reset for {username}.", dialog closes
- On error: inline error message below form

### Sidebar Modification

Add "Users" nav item in the sidebar, conditionally rendered when `authStore.role === "admin"`.

- Icon: lucide `<Users>` (16px)
- Label: "Users"
- Position: in the global nav items section of the sidebar
- Only visible to admin users

## Accessibility Requirements

All interactive elements must meet WCAG 2.1 AA:

- Every `<Input>` has an associated `<Label>` connected via `htmlFor` / `id` -- shadcn/ui `<Form>` handles this
- Error messages are associated with their input via `aria-describedby` -- shadcn/ui `<FormMessage>` handles this
- `<AlertDialog>` traps focus and requires explicit user action -- Radix UI AlertDialog handles this
- `<DropdownMenu>` supports keyboard navigation (arrow keys, Enter, Escape) -- Radix UI handles this
- `<Select>` supports keyboard navigation -- Radix UI handles this
- Table uses semantic `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` elements -- shadcn/ui Table renders these
- Badge text content distinguishes roles (not color alone) -- all badges include readable text labels
- Destructive actions (Deactivate) require explicit confirmation dialog before execution
