  <action>
Create `cmd/flowy-daemon/main.go` mirroring the `cmd/flowy-server/main.go` pattern.

**Implementation:**

```go
package main

import (
    "context"
    "errors"
    "flag"
    "fmt"
    "log"
    "os"
    "os/signal"
    "syscall"

    "github.com/bioflowy/flowy/internal/config"
    "github.com/bioflowy/flowy/internal/daemon"
)
```

1. Parse flags:
   - `--config` (default: "./flowy.yaml") -- path to YAML config
   - `--workers` (default: 0, meaning "use config value") -- override daemon.workers from config

2. Load config via `config.Load(cfgPath)`

3. Apply CLI overrides: if `--workers` > 0, set `cfg.Daemon.Workers = workersFlag`

4. Generate daemon_id as `hostname-PID` format per user decision:
   ```go
   hostname, _ := os.Hostname()
   daemonID := fmt.Sprintf("%s-%d", hostname, os.Getpid())
   ```

5. Create daemon: `d := daemon.New(cfg, daemonID)`

6. Signal handling with `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)`

7. Run daemon in goroutine:
   ```go
   go func() {
       if err := d.Run(ctx); err != nil && !errors.Is(err, context.Canceled) {
           log.Printf("flowy-daemon: run error: %v", err)
       }
   }()
   ```

8. Wait for signal: `<-ctx.Done()`

9. Log shutdown, call `d.Shutdown()`, log stopped.

Keep it simple -- no SQLite, no store. The daemon is a pure HTTP client of the server.
