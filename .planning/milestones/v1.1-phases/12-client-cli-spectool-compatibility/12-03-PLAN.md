<objective>
Replace the local-execution `flowy run` command with a server-based synchronous implementation (submit, poll, print outputs) and update all existing run tests.

Purpose: `flowy run` is the primary user-facing command and must work identically to the spectool test runner's expectations: take a WDL file + inputs, produce JSON outputs on stdout, return exit 0 on success / 1 on failure. The difference is that execution now happens on the server+daemon, not locally. Per user decision, `flowy run --task <name>` also goes through the server via `POST /tasks/run`.

Output: Server-based `runRun` implementation, `pollUntilDone` helper, updated run_test.go with httptest-based tests, and verified `go build ./...` for all three binaries.
</objective>

   - Parse flags: `--input` / `-i`, `--server`, `--config`, `--path`, `--output`, `--quiet`, `--task`, `--verbose`
   - Use `reorderArgs` for spectool compatibility
   - Drop `--dir` flag per CONTEXT.md decision
   - Validate: exactly one positional arg (WDL file path)
   - Load config, resolve server URL

   **If `--task` is provided** (per user decision: `--task` goes through server via POST /tasks/run):
   - **File staging** (reuse `stageInputFiles` and `stageFile` from plan 02): generate UUID, create run dirs, stage WDL and input files (same as workflow path)

   - On success: use returned `resp.RunID`, proceed to poll loop (same as workflow path below)

   **If `--task` is NOT provided** (workflow mode):
   - **File staging** (reuse `stageInputFiles` and `stageFile` from plan 02): same as `runSubmit` — generate UUID, create run dirs, stage WDL and input files
   - Create `client.New(serverURL)`, submit via `client.Submit(ctx, req)`
   - On submit failure: clean up staged dirs, print "error: cannot reach server at <url>: <err>" to stderr, return 1

   **Poll loop (shared for both --task and workflow mode):**
   - Call `pollUntilDone(ctx, c, runID, quiet, stderr)`
   - On COMPLETED: call `client.Outputs(ctx, runID)`, marshal outputs JSON, write to stdout or `--output` file, return 0
   - On FAILED/ABORTED: print `error: workflow FAILED (run: <uuid>)` to stderr, return 1

2. **Implement `pollUntilDone` function:**
   ```go
   func pollUntilDone(ctx context.Context, c *client.Client, runID string, quiet bool, stderr io.Writer) (string, error)
   ```
   - Use `time.NewTicker(2 * time.Second)` for poll interval
   - On each tick: call `c.Status(ctx, runID)`
   - If status poll fails: print warning to stderr, continue (transient network issue)
   - Track `lastState` — only print status to stderr when state changes AND `quiet` is false
   - Status line format: `run <first-8-chars-of-runID>: <STATE>` (e.g., `run abc12345: RUNNING`)
   - On terminal state (COMPLETED, FAILED, ABORTED): return state, nil
   - On context cancellation: return "", ctx.Err()

3. **Set up signal handling in `runRun`:**
   - Use `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)` as root context
   - Pass to submit + poll calls so Ctrl+C interrupts immediately
   - Defer `stop()` from signal context
