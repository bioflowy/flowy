# Requirements: flowy v2.2 Managed File Library

**Defined:** 2026-04-09
**Core Value:** WDL 1.2で記述されたワークフローをDockerコンテナ上で正確に実行できること

## v2.2 Requirements

### File Library

- [x] **FILE-01**: User can view a list of managed files in a project, showing path, file type, size, and creation date
- [x] **FILE-02**: User can delete a managed file record from the library (record-only; does not modify the underlying storage object)

### Import

- [x] **IMPORT-01**: User can import a file into the project library by uploading from their browser
- [x] **IMPORT-02**: User can import a file into the project library by entering an S3/MinIO URI
- [x] **IMPORT-03**: User can import a file into the project library by entering a server-accessible local path (confined to server's storage base directory)

### Auto-Registration

- [x] **AUTOREG-01**: System automatically registers all File and Directory outputs from a completed workflow run as managed files in the project library

### Type Annotation

- [x] **ANNOT-01**: Managed files carry a file type label when the WDL workflow's `parameter_meta` defines a type annotation for that output (for example `parameter_meta { reads: { type: "fastq" } }`)

### File Picker

- [x] **PICKER-01**: User can select a managed file from the project library as input when executing a workflow that has File-typed inputs
- [x] **PICKER-02**: File picker filters the displayed managed files by type when the WDL `parameter_meta` specifies a type constraint for that input field

## Outcomes

- All 9 milestone requirements shipped in phases 38-40.
- Validation evidence was recorded in `docs/v2.2-verification-guide.md`, `go test ./internal/server`, and the targeted web test runs for project files and registry execution dialogs.
- Two late milestone refinements were folded into the shipped outcome: import-time `file_type` submission support and digest-aware registry input lookup with automatic `latest` assignment on push.

## Future Requirements

- Shell-style label templates in `parameter_meta` (for example `label: "${fastq%%.fastq*}.bam"`) remain deferred to a later milestone.
- Source badge and run-provenance links in the Files tab remain useful polish work.
- Search/filter and pagination for larger file libraries remain future UX improvements.

## Out of Scope

- Label template evaluation via system shell
- Cross-project file sharing
- File versioning
- Automatic MIME-type detection for `file_type`
- Deleting underlying storage objects when removing a managed-file record
