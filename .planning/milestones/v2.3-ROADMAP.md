# Milestone v2.3: Managed File Labels & UX

**Status:** ✅ SHIPPED 2026-04-19
**Phases:** 41-43
**Total Plans:** 6

## Overview

v2.3 made the managed-file library easier to read and trace. The milestone added safe shell-style label templates for workflow-generated managed files, explicit provenance metadata for library rows, and targeted browser UX improvements so users can find files faster and understand where they came from.

## Phases

### Phase 41: Label Template Engine

**Goal**: Workflow outputs can derive managed-file labels from workflow input values through a safe, narrow label-template evaluator.
**Depends on**: Phase 40
**Plans**: 2 plans

Plans:

- [x] 41-01: Pure-Go label evaluator and defensive `parameter_meta.label` parsing
- [x] 41-02: Workflow completion integration and regression coverage

**Details:**
Added shared `parameter_meta` parsing helpers and a pure-Go managed-file label evaluator covering `${var}`, `${var%suffix}`, `${var%%suffix}`, `${var#prefix}`, and `${var##prefix}`. Workflow completion now evaluates `parameter_meta.label` during output auto-registration and safely falls back to `filepath.Base(path)` for invalid templates, unsupported forms, or missing variables without invoking a shell.

### Phase 42: File Provenance Metadata

**Goal**: Users can see where a managed file came from and navigate back to the originating run when applicable.
**Depends on**: Phase 41
**Plans**: 2 plans

Plans:

- [x] 42-01: Managed-file source metadata storage and API response updates
- [x] 42-02: Files tab provenance badges and run-link UI

**Details:**
Extended managed-file persistence with `source_type` plus workflow `run_id` provenance, backfilling existing rows during migration. Updated API responses and browser consumers so workflow-generated files, browser uploads, and imports are distinguished explicitly, and workflow-generated rows can link back to their originating run.

### Phase 43: Search and Picker Label Polish

**Goal**: Users can find managed files quickly and see human-readable labels consistently across the file library and workflow launch surfaces.
**Depends on**: Phase 41, Phase 42
**Plans**: 2 plans

Plans:

- [x] 43-01: Files tab search/filter behavior
- [x] 43-02: Label-first picker display and UX regression tests

**Details:**
Added client-side search and file-type filtering to the Files tab, including explicit no-match states. Updated Files rows and the workflow file picker to show labels as the primary text and paths as supporting context, while keeping the underlying form value path-based and preserving manual path entry as a fallback.

## Milestone Summary

**Key Decisions:**

- `parameter_meta.label` remains a pure-Go feature with a deliberately narrow expansion surface; no shell or subprocess execution is allowed.
- Managed-file provenance is modeled explicitly with `source_type` and optional `run_id` rather than inferred heuristically from the path.
- Browser file-selection UX stays path-backed for execution compatibility while moving to label-first presentation.
- Files-tab filtering is client-side because current library sizes do not justify pagination or server-side query complexity.

**Issues Resolved:**

- Managed files can now carry human-readable labels derived from workflow inputs instead of always defaulting to the basename.
- Users can distinguish workflow outputs from manual imports directly in the Files tab.
- Workflow-generated managed files now provide a direct navigation path back to the originating run.
- Files-tab browsing is faster because users can search and type-filter the library without leaving the page.
- The workflow file picker is easier to scan because label-first rendering is consistent with the file library.

**Issues Deferred:**

- Manual label editing for imported files remains future work.
- Pagination and bulk actions for large file libraries remain deferred.
- Broader shell-compatibility beyond the supported prefix/suffix trimming operators remains deferred.

**Technical Debt Incurred:**

- `.planning/REQUIREMENTS.md` and phase verification artifacts lagged behind implementation and were only normalized during milestone closeout.
- Nyquist `*-VALIDATION.md` artifacts were not produced for phases 41-43; the audit records this as process debt, not a product blocker.
- ESLint v9 remains blocked until the repository adopts an `eslint.config.js`.
