### E2E User Flows

**Flow 1: S3 Workflow Submission and Execution**
1. User: `flowy run --storage s3 workflow.wdl -i inputs.json` → CLI validates, submits to server
2. Server: stores run + inputs in SQLite, dispatches tasks with storage config in claim
3. Daemon: claims task, builds S3Backend, localizes inputs, executes in Docker, delocalizes outputs
4. Server: receives outputs via result API, stores in DB, dispatches downstream tasks
5. All phases wired: 15 (CLI/config) → 14 (interface) → 16 (S3Backend) → 17 (daemon LED) → 18 (tested)

**Flow 2: Local Workflow (Backward Compatibility)**
1. User: `flowy run workflow.wdl` → defaults to local storage
2. Server/daemon use LocalBackend — identical to v1.1 behavior
3. All spectool tests pass unchanged (STOR-03 verified)
