## Cross-Phase Integration Issues

### P1 — Sidebar Members Link (Hard Break)

**PROJ-03, PROJ-04 affected**

`Sidebar.tsx` line 68 navigates to `/projects/${activeSlug}/members`, but `App.tsx` has no route for `projects/:slug/members`. The wildcard catch-all renders "Select a page from the sidebar." instead of the members UI.

**Workaround:** Members table is accessible via `/projects/:slug` (Overview link or clicking project card).

**Fix options:**
1. Add `<Route path="projects/:slug/members" element={<ProjectDetailPage />} />` in App.tsx
2. Change sidebar link target to `/projects/${activeSlug}` (Overview already shows members)

### P2 — GET /users Missing Admin Guard

**USER-01 affected (security)**

`GET /users` in `server.go` line 122 only requires JWT authentication, not admin role. Any authenticated non-admin user can enumerate all users via direct API call or URL navigation. The sidebar hides the link for non-admins, but this is a UI-only gate.

**Fix:** Add `roleRequired("admin")` middleware to `GET /users` route.

**Note:** This was an intentional relaxation in Phase 28 to allow the Add Member dropdown to show available users for non-admin project admins. May need a separate endpoint (e.g., `GET /projects/{slug}/available-users`) instead.

### P3 — Auth-Disabled Mode UX Dead End

**AUTH-01 affected (dev mode only)**

When `auth.enabled=false`, `handleLoginDisabled` returns `token: ""`. `LoginPage.tsx` silently returns without redirecting — user stays on login screen with no feedback. Only affects development/testing without auth.
