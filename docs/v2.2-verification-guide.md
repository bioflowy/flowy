# v2.2 動作確認ガイド

v2.2 マイルストーン「Managed File Library」で追加された機能の確認手順です。対象は以下です。

- プロジェクト単位の managed file library
- Files タブでの一覧表示とレコード削除
- Browser Upload / S3 URI / Server Path によるファイル取り込み
- ワークフロー完了時の File / Directory 出力の自動登録
- `parameter_meta.type` による `file_type` の付与
- Run Workflow ダイアログでの managed file picker と型フィルタ

## 前提条件

```bash
# サーバー・デーモン・UI を起動
make dev

# 停止するとき
make dev-stop
```

以下の前提で記載します。

- UI は `http://localhost:3000`
- API は `http://localhost:8080`
- 確認対象プロジェクトのスラッグは `test-project`
- `executor` 以上のロールを持つユーザーでログインできる

補足:

- **S3 URI import** を確認するには、`flowy.yaml` で `storage.type: s3` と対象バケットが設定されている必要があります
- **Server Path import** を確認するには、`flowy.yaml` で `import_root` が設定され、その配下に実在ファイルが必要です

---

## 1. Files タブの表示確認

1. ブラウザで `http://localhost:3000` を開き、`executor` 以上のロールのユーザーでログイン
2. `test-project` の Project Detail ページを開く
3. 画面上部に `Members` と `Files` の 2 つのタブが見えることを確認
4. `Files` タブをクリック

**期待結果:**

- `Files` タブに切り替わる
- 一覧テーブルに `Path` / `Type` / `Size` / `Created` の列が表示される
- `executor` / `admin` では **Import File** ボタンが表示される
- `viewer` では Import / Delete 操作が表示されない

---

## 2. Browser Upload での取り込み確認

1. `Files` タブで **Import File** をクリック
2. ダイアログで `Browser Upload` を選択
3. 任意のローカルファイルを選ぶ
4. 必要なら `File Type` に `fastq` などを入力
5. **Import File** をクリック

**期待結果:**

- `File imported.` のトーストが表示される
- ダイアログが閉じる
- Files 一覧に新しい行が追加される
- `Path` はサーバー側の保存先パスになる
- `File Type` を入力した場合は `Type` 列にその値が表示される
- `File Type` を空のままにした場合は空欄表示（`—`）になる
- `Size` と `Created` が埋まる

---

## 3. S3 URI での取り込み確認

この手順は S3/MinIO バックエンド利用時のみ実施します。

1. `Files` タブで **Import File** をクリック
2. ダイアログで `S3 URI` を選択
3. 例として `s3://<configured-bucket>/path/to/sample.fastq.gz` を入力
4. 必要なら `File Type` に `fastq` などを入力
5. **Import File** をクリック

**期待結果:**

- 成功時は `File imported.` のトーストが表示される
- Files 一覧に `Path = s3://...` の行が追加される
- `Label` は URI の末尾ファイル名由来になる
- `File Type` を入力した場合は `Type` 列にその値が表示される
- サイズは `HeadObject` 相当の結果で埋まる

**エラーケース:**

- 設定外バケットを指定するとエラーになる
- 存在しないオブジェクトを指定するとエラーになる

---

## 4. Server Path での取り込み確認

この手順は `flowy.yaml` で `import_root` を設定している場合のみ実施します。

事前に `import_root` 配下へテストファイルを 1 つ置いておきます。

例:

```bash
mkdir -p /tmp/flowy-imports
printf 'hello\n' > /tmp/flowy-imports/sample.txt
```

設定例:

```yaml
import_root: /tmp/flowy-imports
```

手順:

1. `Files` タブで **Import File** をクリック
2. ダイアログで `Server Path` を選択
3. `import_root` 配下の絶対パスを入力
   例: `/tmp/flowy-imports/sample.txt`
4. 必要なら `File Type` に `report` などを入力
5. **Import File** をクリック

**期待結果:**

- 成功時は `File imported.` のトーストが表示される
- Files 一覧に対象ファイルが追加される
- `File Type` を入力した場合は `Type` 列にその値が表示される

**境界チェック:**

1. 今度は `import_root` の外側のパスを入力
   例: `/etc/hosts`
2. **Import File** をクリック

**期待結果:**

- エラーになる
- `import_root` 外のパスは取り込めない

## 5. Files タブからの削除確認

2. 確認ダイアログで **Delete** をクリック

**期待結果:**

## 6. 自動登録と `file_type` 付与の確認

この確認では、`parameter_meta.type` を持つ File 入力・出力を含む workflow を使います。

例:

```wdl
version 1.0

workflow managed_file_demo {
  input {
    File reads
  }

  parameter_meta {
    reads: {
      type: "fastq"
    }
    aligned_bam: {
      type: "bam"
    }
  }

  call make_copy {
    input:
      src = reads
  }

  output {
    File aligned_bam = make_copy.out
  }
}

task make_copy {
  input {
    File src
  }

  command <<<
    cp "~{src}" out.bam
  >>>

  output {
    File out = "out.bam"
  }
}
```

### 6a. レジストリ登録

```bash
flowy registry push --project test-project --name managed-file-demo managed-file-demo.wdl
```

必要なら tag も付けます。

```bash
flowy registry list --project test-project
```

**期待結果:**

- レジストリに workflow が登録される
- UI の Registry 画面からも見える

### 6b. ワークフロー実行

1. Registry の対象エントリページを開く
2. **Run** をクリック
3. `reads` に既存の FASTQ ファイルを指定して実行
4. 実行完了まで待つ

**期待結果:**

- Run が `COMPLETED` になる
- 失敗せず outputs が保存される

### 6c. Files タブでの反映確認

1. Project Detail に戻る
2. `Files` タブを開く

**期待結果:**

- 実行で出力された `aligned_bam` が自動で登録されている
- その行の `Type` に `bam` が表示される
- workflow が `Directory` または `Array[File]` / `Array[Directory]` を返す場合は、各要素が個別行として登録される
- 同一 run 内で同じ path が複数回現れても、重複レコードは 1 件にまとまる

## 7. Run Workflow ダイアログの managed file picker 確認

### 7a. picker の表示確認

1. Registry の workflow エントリページを開く
2. **Run** をクリック
3. `File` 型入力がある workflow を選ぶ

**期待結果:**

- File 型入力に対して、従来の手入力欄に加えて managed file picker が表示される
- picker の下に「プロジェクトの file library から選ぶか、手動 path を入力する」旨の説明が表示される

### 7b. `parameter_meta.type` によるフィルタ確認

1. Files タブ側で、異なる `Type` を持つファイルを複数用意しておく
   例: `fastq`, `bam`, 空欄
2. `parameter_meta { reads: { type: "fastq" } }` を持つ workflow の Run ダイアログを開く

**期待結果:**

- picker には `Type = fastq` のファイルだけが候補表示される
- `bam` や空欄のファイルは候補に出ない
- 説明文にも `Showing only files tagged "fastq".` 相当の注記が出る

### 7c. manual path fallback の確認

1. picker を使わず、手入力欄に直接パスを入れる
2. 実行する

**期待結果:**

- 既存どおり手入力 path でも実行できる
- picker は補助機能であり、manual path は引き続き利用可能

## 8. API レベルの確認

必要に応じて `curl` でも確認できます。

### 8a. 一覧取得

```bash
curl -H "Authorization: Bearer <TOKEN>" \
  http://localhost:8080/projects/test-project/files
```

**期待結果:**

- `files` 配列が返る
- 各要素に `id`, `path`, `file_type`, `label`, `size`, `created_at` が含まれる

### 8b. JSON 取り込み

```bash
curl -X POST \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"uri":"s3://<bucket>/path/to/file.fastq.gz"}' \
  http://localhost:8080/projects/test-project/files
```

### 8c. multipart 取り込み

```bash
curl -X POST \
  -H "Authorization: Bearer <TOKEN>" \
  -F "file=@./local-input.fastq.gz" \
  http://localhost:8080/projects/test-project/files
```

### 8d. 削除

```bash
curl -X DELETE \
  -H "Authorization: Bearer <TOKEN>" \
  http://localhost:8080/projects/test-project/files/<FILE_ID>
```

**期待結果:**

- 成功時は HTTP 204
