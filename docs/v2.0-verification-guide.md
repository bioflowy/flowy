# v2.0 Web UI 動作確認ガイド

v2.0 マイルストン「Web UI — Management」の実装を手動で確認する手順です。

## 前提条件

- Go 1.24+ がインストール済み
- Node.js 20+ がインストール済み
- Docker が起動中（ワークフロー実行テスト時に必要）

## 1. ビルド

```bash
# フロントエンドのビルド + flowy-ui バイナリの生成
make build-ui

# flowy-server のビルド
go build -o ./flowy-server ./cmd/flowy-server
```

## 2. サーバー起動

### 方法A: 開発モード（Vite dev server + flowy-server）

ターミナル1: バックエンドサーバー起動
```bash
# 初回のみ: 管理者ユーザー作成
./flowy-server --config ./flowy.yaml --init-admin --username admin --password admin123

# サーバー起動（CORS有効化が必要）
./flowy-server --config ./flowy.yaml
```

`flowy.yaml` に CORS 設定を追加:
```yaml
cors:
  enabled: true
  allowed_origins:
    - "http://localhost:5173"
```

ターミナル2: フロントエンド開発サーバー起動
```bash
cd web
npm install   # 初回のみ
npm run dev
```

ブラウザで http://localhost:5173 にアクセス。

### 方法B: 本番モード（flowy-ui バイナリ）

```bash
# flowy-server を起動（CORSは不要）
./flowy-server --config ./flowy.yaml &

# flowy-ui を起動（SPAを配信 + /api/* をflowy-serverにプロキシ）
./flowy-ui --api-addr http://localhost:8124 --addr :3000
```

ブラウザで http://localhost:3000 にアクセス。

### 3.4 レジストリ閲覧 (Phase 29)

事前準備: CLI でレジストリにエントリをプッシュしておく。

```bash
# ワークフローをレジストリにプッシュ（例）
./flowy registry push --project <slug> --name my-workflow --kind workflow path/to/workflow.wdl
./flowy registry push --project <slug> --name my-tool --kind tool path/to/tool.wdl
```

| # | 操作 | 期待結果 |
|---|------|----------|
| 1 | サイドバーの「Registry」をクリック | レジストリエントリ一覧テーブル表示。Name, Kind（バッジ）, Versions, Tags, Created 列 |
| 2 | Kind列のバッジ確認 | tool=青バッジ、workflow=紫バッジ |
| 3 | エントリ行をクリック | エントリ詳細ページ: バージョン履歴テーブル（digest, tags, 日付） |
| 4 | バージョンを選択（またはデフォルトの最新版） | WDLソースコードが行番号付きコードブロックで表示される |
| 5 | コピーボタンをクリック | WDLソースがクリップボードにコピーされる |
| 6 | admin ユーザーで「Create Tag」ボタン | タグ名とバージョンdigestを選択するダイアログ |
| 7 | タグを作成 | エントリ一覧にタグが反映される |
| 8 | タグを削除（確認ダイアログ付き） | タグが即座に消える |
| 9 | viewer ロールのユーザーでアクセス | タグ作成/削除ボタンが表示されない（admin のみ） |

### 3.5 ファイル閲覧 (Phase 30)

事前準備: ワークフローを実行してランを作成しておく。

```bash
# プロジェクトスコープでワークフロー実行（例）
./flowy run --project <slug> path/to/workflow.wdl -i input_file=path/to/input.txt
```

| # | 操作 | 期待結果 |
|---|------|----------|
| 1 | サイドバーの「Runs」をクリック | ラン一覧テーブル: Run ID, Status（色付きバッジ）, Source, Started, Duration |
| 2 | ステータスバッジの色確認 | Completed=緑, Running=黄, Failed=赤, Pending=灰 |
| 3 | 完了したラン行をクリック | ラン詳細ページ: メタデータヘッダー + アウトプットテーブル |
| 4 | アウトプットテーブルのファイル出力行 | 「File」バッジと「Download」ボタンが表示される |
| 5 | 「Download」ボタンをクリック | ブラウザのダウンロードダイアログが表示され、ファイルがダウンロードされる |
| 6 | テキストファイル出力の「Preview」ボタンをクリック | 行の下にコードブロックが展開され、ファイル内容がインライン表示される |
| 7 | 「Hide Preview」をクリック | プレビューが折りたたまれる |
| 8 | 文字列/数値型の出力（ファイルではない出力） | 値がテキストとしてインライン表示される（ダウンロードボタンなし） |
| 9 | 未完了のラン行をクリック | ステータスに応じたメッセージ表示（アウトプットテーブルは非表示） |

## 4. 自動テストの実行

```bash
# フロントエンドテスト（111テスト）
cd web && npx vitest run --reporter=verbose

# バックエンドテスト（サーバーハンドラ）
cd .. && go test ./internal/server/... -v

# バックエンドテスト（ストア）
go test ./internal/store/... -v

# TypeScript型チェック
cd web && npx tsc --noEmit
```

全テストがパスし、TypeScript のコンパイルエラーがないことを確認してください。

## 5. 確認済みの既知の制約

- レジストリエントリの作成は CLI (`flowy registry push`) のみ。UIからの作成はサポートしない設計
- ランの一覧にページネーションなし（v2.0 スコープ外、将来対応予定）
- WDL ソースコードの構文ハイライトなし（WDL は主要ハイライトライブラリに未対応のため、プレーンテキスト表示）
- ファイルプレビューは 100KB 以下のテキストファイルのみ対応
- S3 バックエンドからのダウンロードはサーバープロキシ経由（Presigned URL 未対応）
