# v2.1 動作確認ガイド

v2.1 マイルストーン「Job Execution & Registry CLI」で追加された機能の確認手順です。

## 前提条件

```bash
# ビルドして全コンポーネントを起動（サーバー・デーモン・UI）
make dev

# 停止するとき
make dev-stop
```

テスト用のプロジェクトとユーザーが必要です。以下では `test-project` というスラッグのプロジェクトに、`executor` ロールのユーザーが存在する前提で記載します。

---

## 1. CLI ログイン（Phase 33: CLI-01, CLI-02）

```bash
# ログイン — トークンが ~/.flowy/credentials.yaml に保存される
flowy login --server http://localhost:8080 --username <ユーザー名> --password <パスワード>

# 確認: 認証ファイルが作成されていること
cat ~/.flowy/credentials.yaml
```

**期待結果:** `token:` フィールドにJWTトークンが保存されている。以降のCLIコマンドで `--token` フラグが不要になる。

---

## 2. CLI レジストリ操作（Phase 33: REG-CLI-01〜05）

```bash
# WDL ファイルをレジストリにプッシュ
flowy registry push --project test-project --name hello-wf hello.wdl

# レジストリ一覧を表示
flowy registry list --project test-project

# WDL ソースをプル
flowy registry pull --project test-project --name hello-wf

# タグを作成
flowy registry tag --project test-project --name hello-wf --tag v1 --digest <ダイジェスト>

# タグを削除
flowy registry delete-tag --project test-project --name hello-wf --tag v1

# エントリを削除（admin ロールが必要）
flowy registry delete --project test-project --name hello-wf
```

**期待結果:** 各コマンドがエラーなく実行され、レジストリの状態が更新される。

---

## 3. ブラウザからの WDL アップロード（Phase 34: REG-UI-01）

1. ブラウザで `http://localhost:3000` にアクセスし、executor ロールのユーザーでログイン
2. プロジェクトの **Registry** ページに移動
3. **Push WDL** ボタンが表示されていることを確認
4. ボタンをクリック → ダイアログが開く
5. エントリ名を入力し、`.wdl` ファイルを選択して送信

**期待結果:**
- 成功トーストが表示され、エントリ名・ダイジェスト・種別バッジが確認できる
- エントリ一覧が自動更新される
- viewer ロールのユーザーには Push WDL ボタンが表示されないこと

---

## 4. 実行ステータスのポーリング（Phase 35: EXEC-04）

1. CLI でワークフローを投入:
   ```bash
   flowy run --project test-project hello-wf:latest
   ```
2. ブラウザで **Runs** ページを開く

**期待結果:**
- PENDING / RUNNING 状態のランの横に **黄色い点滅ドット** が表示される
- ランの一覧が約3秒ごとに自動更新される（ブラウザのネットワークタブで GET リクエストを確認）
- ランが COMPLETED / FAILED / ABORTED になると、点滅ドットが消え、ポーリングが停止する
- 完了済みランの詳細ページを直接開いた場合、ポーリングリクエストが発生しないこと
- ブラウザタブを非表示にすると、ポーリングが一時停止すること（タブに戻ると再開）

**ランの詳細ページ:**
- RUNNING 中、実行時間の表示が1秒ごとに更新される（3秒刻みではない）

---

## 5. ブラウザからのワークフロー実行（Phase 36: EXEC-01〜03, EXEC-05）

### 5a. Run ボタンの表示確認

1. レジストリエントリページ（例: `/projects/test-project/registry/hello-wf`）に移動
2. executor / admin ロールのユーザーで **Run** ボタンが表示されることを確認
3. viewer ロールのユーザーでは Run ボタンが表示されないことを確認

### 5b. 実行ダイアログの確認

1. **Run** をクリック → RunWorkflowDialog が開く
2. バージョン/タグのドロップダウンが表示され、デフォルトで `latest` が選択されている
3. ワークフローの入力パラメータに応じたフォームフィールドが動的に生成される:

   | WDL 型 | 表示されるコントロール |
   |--------|----------------------|
   | String | テキスト入力 |
   | Int    | 数値入力（step=1） |
   | Float  | 数値入力（step=any） |
   | Boolean | チェックボックス |
   | File   | テキスト入力 + ツールチップアイコン |
   | Array / Map / Struct | JSON テキストエリア |

4. File 型のフィールドにツールチップアイコン（ℹ️）が表示され、ホバーすると「サーバーからアクセス可能なパスを入力してください（例: `s3://` や絶対パス）」という説明が表示される

### 5c. 送信と結果確認

1. 必須フィールドを入力して **Run Workflow** をクリック
2. 「Run submitted.」というトーストが表示される
3. 自動的に RunDetailPage に遷移する
4. Phase 35 のポーリングにより、ランの状態がリアルタイムで更新される
5. ランが完了すると、**Outputs** セクションにワークフローの出力ファイルが表示される
6. ファイルのダウンロードとプレビューが動作すること

### 5d. エラーケースの確認

- 必須フィールドを空のまま送信 → バリデーションエラーが表示される
- バージョンを切り替えると → フォームがリセットされ、新しい入力項目が表示される

## 既知の制限事項

- File 型の入力はサーバー上のパス（`s3://` や絶対パス）の手動入力のみ対応。ブラウザからのファイルアップロードは v2.2 以降で対応予定
- Array / Map / Struct 型の入力は JSON テキストエリアでの入力。専用ウィジェットは v2.2 以降で対応予定
- WebSocket/SSE によるリアルタイム更新は未対応（ポーリング方式を採用）
